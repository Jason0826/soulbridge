## 三、只能人来决定的四件

1. **`holder` 的声明**（`term-audit` 现在就红在这）：改名字变成"层词 + 实体 id"两档，还是补成三层值域？
2. **`type_name` 收不收敛**：466 个值、322 个孤例。它已经不参与路由（ADR 0027），要么**退出提示词**（不再让它生成标签），要么**给它一张受控词表**。
3. **`supersede()` 接上还是删掉**：新结论取代旧结论，现在没有业务路径调用它。
4. **`lesson` 与 `disposition` 二选一**：两者都表示"遇到这种情形该怎么做"，不能都留。

### 一个必须补的缺口：新设计把判据 3 弄丢了

0030 的三条验收线是 A 交代成本（≈判据 1）、B 识别率（≈判据 1·2）、C 溯源率（≈判据 4）。
**判据 3「没记岔」在三兄弟里没有对应项**——而它恰恰是用户最不能忍的一种失败（"你记错了/不是这样"）。

所以债表顺带改一个设计：**0030 补第四条线 D 记岔率**（口径：抽查 20 条"我记得…"陈述里，内容与来源不符的条数），而 `supersede()` 是它的机制。**机制和指标一起上，否则修完了没法判它对不对。**

### 重排后的顺序

```
第一步（判据 3）  把"取代时能看见多少旧事实"从最新 12 条改成按实体/主题取，够用为止
                 并让 type_name 退出提示词
第二步（判据 2）  停掉 catalog 注入，把预算还给真正会被用的东西
第三步（工程底线）消 6 组重复声明；删无消费者的死路径
第四步（判据 1）  清 lesson/disposition 撞名 + holder 声明 → 才开 0030
并行（判据 4）    C 的 20 条抽样是离线零成本，随时可跑
```

### 误判记录：`supersede()` 没有坏

我一开始把健康检查那条「`supersede()` 有实现但没有业务调用者」读成"新结论取代不了旧结论"，并按这个排了优先级。**查下去是错的**：

```
supersedeFact(oldId, newId) 有 3 个业务调用点（index.ts:912 / 1022 / 1225）+ 插件 1 个（index.js:2544）
库里 79 条已取代 → 路径是通的
那条 WARN 说的是旧 memories 表的 supersede()（16 行历史数据），不是 facts
```

留痕有两个原因：一是我拿错误结论排过序；二是**检查的措辞也会误导人**——"有实现但没有调用者"必须点名是哪个实现，否则读的人会得出相反结论。

## 五、判据 3 的修法：候选阶梯（2026-11-10 21:10，待拍）

用户提的口径：**实体 + 场合 + 时间，硬 + 软，取不到再逐级放宽**——保证"不会太多又精确"。
落到现在的库里，先看三维各自能查到什么：

| 维度 | 现状 | 数 |
|---|---|---|
| 实体 | `fact_slots.entity_id` 只覆盖 **354 / 1366 条**（26%） | 74% 的事实按实体取不到 → **必须留兜底** |
| 场合 | **不存在**。`场合` 是 0030 要加的槽，代码里一行没有 | 用**线索**当替身（线索 ≈ 当时在聊什么） |
| 时间 | 1322/1366 有 `valid_from`，其中 `unknown` 579（42%） | 能粗排，不能当硬筛 |

拿最近一条真实线索实测（`th_mw207u2d_mj90` = 换会话丢多少理解）：

```
级 1  本线索里的事实                    17 条   ← 精确，够用就不放
级 2  线索内 2 个实体的跨线索事实       72 条   ← 抓矛盾的关键，要截断
级 3  最近 12 条（现状）                  —     ← 只在前两级都空时兜底
（对照：最近 7 天新增 835 条 —— 时间窗当筛子太粗，只用来排序）
```

所以阶梯是：

```
封顶 30 条，按「同线索 > 同实体 > 时间近」排
级 1 凑满 30 → 到此为止
不够 → 级 2（该线索实体的跨线索事实，按时间近补到 30）
还不够 → 级 3 最近 12 条
截断要记账：丢了几条、为什么丢（规则 18）
```

**"软"放在哪**：软不写进代码筛。候选是硬取的 30 条，**相关与否由模型在抽取时自己判**——同一次调用，不加成本，也不违反 ADR 0027（代码不猜意思）。

成本：12 条 → 30 条，每条约 30 字 ≈ **+540 字 ≈ +360 token/轮**，离峰约 ¥0.0004/轮。

**验收（改完当场可验）**：跟它说一句「发布那事怎么样了」，它应写 `noop` 或 `操作=取代 <旧 id>`，**而不是新写第 19 条发布状态**。

## 六、怎么防止再欠

```
1. 每个 brief 顶部写「退场条件」：什么算做完、做完之后哪段代码/文档下台
2. 一条线没写退场条件就不开工；两条以上并行必须在本文登记
3. 每周跑 term-audit + health-check，本文的数字跟着更新；不更新就说明没 review
```

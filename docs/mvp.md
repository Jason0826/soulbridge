## 为什么要有这个文件

S1 的效果目标是"连续用一周，我不需要重复解释同一件事"。它的问题是：

- **太长**——要一周才知道成不成
- **太依赖日积月累**——用户得碰巧遇到"同一件事"
- **判据靠感觉**——"重复解释"没有客观边界

结果就是 S1 收口时两条判据"无法判定"。

**MVP 换一种定义方式：用户能当场看到什么。**

每个 MVP 都是一句话能说清、几分钟能验完的能力。阶段按 MVP 切，而不是反过来。

## 三个 MVP

| MVP | 用户能感知的行为 | 需要的底层能力 | 状态 |
|---|---|---|---|
| **MVP1** | "它接得上我们上次聊的" | `turn_pair` + 召回 + 注入 | **机制完成（0.0.89），验收未做** |
| MVP2 | "它知道我是个什么样的人" | 归纳 + 画像 | **骨架在（画像 9 条 / 4 of 7 维），活水未通** |
| MVP3 | "它记住的事能变成动作" | `trigger`（条件→动作） | **演示级（规则 62 条，触发率 19%），缺度量** |

> 状态列的依据与实测数字见 [state.md](state.md) 第三节；本文只定义"什么算过"。
> MVP1 判据（本文第 54–62 行）仍是唯一有效的收口标准：**跨会话连做 3 次，对 ≥2 次，且没有编。**

**顺序不能换**：MVP1 是地基（连交流都记不下来，谈"人"和"触发"都是空的）。

## MVP1：关掉再打开，它能接上

### 场景

```
1. 正常用 DSH 聊一段（有来有回，有决定，有事实）
2. 完全关掉 DSH
3. 重开，新建会话（上下文为空）
4. 问一句："我们上次聊到哪了？"
```

### 期望

它说出三样东西，且都对：

1. **上次聊的主题**（交流内容，不是零散条目）
2. **你当时的决定/立场**（比如"你决定先不改代码，等观察数据"）
3. **一件关于你的稳定事实**（比如"你在做企业内部落地的记忆方案"）

### 验收

| 条件 | 通过线 |
|---|---|
| 连做 3 次，说对的次数 | ≥ 2 |
| 说对的定义 | 主题对、决定对、事实对，且**没有编** |
| 用户的判断 | "这算记得我" |

**第 3 条是最终判据。**前两条只是它的分解——如果数字到了但你觉得不像，那还是没过。

### 失败形态（明确写出来）

- 说不出来（空召回）
- 说出来但错（记岔）
- 说出来但编（把推测当成记忆）
- 说出来了，但内容是"最近一轮"而不是"上次"（说明只用了会话内上下文，记忆没起作用）

最后一条最隐蔽：**要确认它用的是记忆，不是残留的上下文。**

### 需要什么

```
turn_pair 落库           ← 一问一答，双向（见 0010 §4）
     ↓
新会话消息 → 召回
     ↓
注入 → 模型组织成回答
```

**不需要**：画像、归纳、触发动作、实体图谱。

### 顺便验证了什么

- **S1 判据 2（记忆真被用上）**：接得上就是最直接的"用上"
- **`ids` 日志**：能看到那次回答注入了哪几条
- **BM25**：新会话的问题和旧片段靠词面能不能连上

### 没验证的（别当成结论）

- 中文场景下的召回质量（LongMemEval 是英文）
- 归纳能不能产出有用的画像（那是 MVP2）
- 记忆能不能触发动作（那是 MVP3）

## 与阶段的关系

- 阶段按 MVP 切，一个阶段完成一个 MVP
- 阶段文件仍然写：效果目标、判据、预算、范围内/外——**只是效果目标引用对应 MVP**
- MVP 完成后才开下一个；不允许"一边做 MVP1 一边设计 MVP3"

## 维护

MVP 是产品定义，不随阶段变。**改它需要在阶段收尾或开工时明确决定**，不能中途悄悄改。

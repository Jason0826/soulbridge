# 命题：记忆不是容量，是人格

这份文档是这个项目唯一的判据。
**任何功能、任何机制，都要回答"它服务于这个命题吗"。答不上来的，删。**

---

## 一、核心命题

> **为"容量"而生的记忆方案，会随上下文窗口变大而贬值；**
> **为"选择与人格"而生的，不会。**

推理链：

1. RAG、知识图谱、长文档切块，解决的是"装不下"
2. 上下文窗口（和硬件）在持续变大 → 容量型方案的价值被稀释
3. 但即使窗口无限大，注意力不是均匀的、成本不是免费的、遗忘不是缺陷
4. 因此**选择（该想起什么）、时序（什么时候想起）、情绪加权（想起时带什么权重）** 不会被淘汰
5. 这三样合起来，就是"人格"

## 二、两个推论

**推论 A：记忆层会商品化。**
存储、检索、切块、去重、连接器——会有（已经在有）成熟产品。自己造这一层，投入产出比会持续下降。

**推论 B：记忆之上的"行为层"不会商品化。**
因为它依赖具体宿主的上下文格式、依赖这个 soul 的历史、依赖"被纠正过什么"。没有一个通用服务能替你做。

**战略结论：做行为层，买记忆层。**

## 三、三条可证伪预测

| # | 预测 | 如果被证伪 |
|---|---|---|
| P1 | 人格型记忆的收益**不随**上下文窗口增大而消失 | 退回做检索层，或放弃项目 |
| P2 | 人格型记忆的收益来自"选择+时序+权重"，而不是"存得更多" | 说明只是 RAG 的变体，没有独立价值 |
| P3 | 同一 soul 跨两个宿主使用时，重复提问率显著低于单宿主 | 跨宿主连续性不成立，"一个 soul 多个宿主"的定位作废 |

三条里任何一条被证伪，都要改方向。**P1 是生死线。**

## 四、四臂实验（决定 P1）

```
同一批任务（复用 soulkernel 的 memory eval case）
同一模型
四个臂：

  A  无记忆                        （基线）
  B  全量上下文塞进去               （容量型，越长越好）
  C  事实检索                      （RAG，容量型 + 选择）
  D  人格层（事实+身份+情绪+策略+反思）（选择型 + 人格）

在 8k / 128k / 1M 三档上下文下各跑一遍
每个 case 跑 N=3，取中位数
```

**指标**（按重要性）：

1. **重复犯错率**——同类纠正 30 天内是否复发（主指标）
2. **风格一致性**——同一 soul 前后语气/判断是否连贯（人工抽样 + LLM 盲评）
3. **任务成功率**——常规指标，用来确认没退化
4. **成本**——每任务 token 与延迟

**预测**：

- B 在 8k 时显著差，在 1M 时追平或超过 C
- D 在所有档位稳定高于 C
- C 与 B 的差距随上下文增大而缩小（容量型方案的收益衰减）

**判定**：

| 结果 | 结论 |
|---|---|
| D 的优势随窗口增大而消失 | P1 被证伪 → 停止做人格层 |
| D 的优势稳定存在 | P1 成立 → 这是项目最核心的对外证据 |
| D 只在 8k 有优势 | 描述为"小窗口下的增强"，不要夸大 |

## 五、这个命题的边界

它**不**主张：

- AI 有意识、有主观体验
- 应该给 AI 自主目标
- 人类记忆在机制上等价于这套设计

它**只**主张：在"有限注意力 + 持续交互"的条件下，**选择型记忆比容量型记忆更有长期价值**。

这是一条工程命题，可以被实验检验。**不要让它变成信仰。**

## 六、与产品的关系

| 命题 | 产品形态 |
|---|---|
| 选择 > 容量 | 不做向量数据库，做注入策略 |
| 人格需要时序 | 记忆有 `valid_from` / `superseded_by` / 遗忘曲线 |
| 人格需要关系 | 私有记忆与共享记忆分离 |
| 行为层不可外包 | 注入、反思、评估三件事必须自研 |
| 跨宿主才成立 | 一个 soul 接多个 agent，是本项目唯一的结构性空位 |

## 七、什么情况下放弃

提前写清楚，省得自欺：

1. P1 被实验否定
2. 接入第二个宿主需要改核心 → 抽象错了
3. 真实使用两周，用户（包括你自己）感觉不到差别
4. 宿主平台原生提供了等价能力，且跨工具可用

**第 4 条不是失败，是市场判断——但只有前三条先排除，才有资格谈第 4 条。**

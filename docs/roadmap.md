## 一、当前阶段：MVP1 收口

`mvp.md` 的判据没变，也只有一个：

```
关掉 DSH → 重开 → 新会话问"我们上次聊到哪了？"
连做 3 次，对 ≥2 次，且没有编
```

机制全在（turns/steps、线索、归纳、handoff 注入），**只差真跑一次**。
在它通过之前，MVP2/MVP3 的功能不再往前加——这是 mvp.md 写的规矩，不是我的偏好。

## 四、明确不做

- 平台化（并发引擎 / 编译器 / 蜂群）
- Python / Rust 双运行时（破坏零依赖）
- 30+ 工具面（默认四个动词）
- 自建云服务

## 五、改这份文件的规矩

1. 新方向必须先改这里，并写明**挤掉了上面哪一项**。
2. 任何改动**同步更新**它影响的文档（state.md / mvp.md / ADR / briefs），做不到就别合。
3. 这条以前只是口头约定，现在有检查：`scripts/health-check.mjs` 4.7 会比对 `state.md` 的核对日期与代码最后提交日期，**文档落后于代码就 WARN**。

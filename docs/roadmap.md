## 当前重心：把 DSH 用好

在第二个宿主真正投入使用之前，所有开发都服务 DSH。

### N1. DSH 工具：`soul_recall` / `soul_remember`

当前模型无法在任务中途主动查记忆，只能靠开场注入。

- 验收：在 DSH 里问"我记得你之前说过什么"时，模型能调 `soul_recall` 取到
- 消费者：DSH 会话中的模型本身

### N2. 审计留痕

`list` 看不到每条记忆是**哪条规则/哪次模型调用**写的。

- 验收：`soulbridge list --audit` 显示来源（rule id 或 `llm`）
- 消费者：排查误记的用户（你）

### N3. 长会话提醒

按真实用户回合计数，每 10 轮提醒归档一次。

- 验收：第 10、20 轮各出现一次，只出现一步
- 消费者：DSH 长会话

## 条件触发（不排期，满足条件才做）

### C1. MCP 适配器（跨宿主）

**启用条件**：出现第二个**正在使用**的宿主（每天用它干活），而不只是"以后可能"。
MCP 只给"可查的记忆"，不给自动注入/自动观察——那需要宿主钩子。在那之前不做。

一个 `soulbridge-mcp`（stdio JSON-RPC）覆盖 Claude Code / Codex CLI / ZCode 等；
DSH 插件保留，因为只有它能拿 `session/event`（自动观察）。

- 工具：`soul_context` / `soul_observe` / `soul_recall` / `soul_remember`
- 验收：从任意 MCP 宿主调用 `soul_context` 能拿到同一份注入文本

### N2. 规则写入的三道闸门 + `committed` ✅ 已完成（0.0.14）

当前 `observe` 直接写库。借鉴灵枢："记什么、能不能写入由确定性规则裁决，过闸门后
以 `committed` 确认，绝不假装成功"。

```
候选 → 闸门1 形状（长度/类型/去重）
     → 闸门2 语义（是否含指令性、是否与已有记忆冲突）
     → 闸门3 预算（条数上限、注入预算）
     → committed
```

- `ObserveResult` 增加 `committed: boolean`（与实际写入行数一致）
- 验收：任一闸门拒绝时 `written=0, committed=false`，且能说明是哪道闸门

### N3. 时效与冲突 ✅ 已完成（0.0.15）

`Memory` 已有 `validFrom` / `validUntil` / `supersededBy`，但没有任何代码使用。

- 检索时按 `validUntil` 过滤（借鉴其 `validity=true`）
- 新记忆与旧记忆冲突时，旧的置 `superseded` 并写 `supersededBy`（不删除）
- 验收：同一事实两次写入（内容不同）→ 旧的变成 superseded，注入只出现新的

### N4. 审计留痕

每次写入/遗忘记录"谁、何时、为什么"（规则 id 或模型来源）。当前只有墓碑，没有原因。

- 验收：`soulbridge list --audit` 能看到每条记忆的来源规则

### N5. 长会话提醒

借鉴灵枢：按**真实用户回合**计数（不是 system prompt 组装次数），每 10 轮提醒一次归档。

- 验收：第 10、20 轮各出现一次提醒，只出现一步

## 借鉴清单（来自灵枢，逐条对应到我们的代码）

| 借鉴点 | 它的做法 | 我们的落点 | 优先级 |
|---|---|---|---|
| 三道闸门 + `committed` | 写入必经裁决，未确认不算成功 | `observe` 写入路径 | N2 |
| 原文即真源，索引为派生 | md 为真源，索引可重建 | `keywords` 只用于评分，可重建 | 已隐含，需文档化 |
| 分层写入闸门 | contextual→knowledge→structural→self | B 阶段 `pending` 审批（已改 RFC 0003） | B 阶段 |
| 时效过滤 + 冲突检测 | `validity=true`、冲突置 superseded | N3 | 高 |
| 审计留痕 | 每次写入可追溯 | N4 | 中 |
| 长会话提醒 | 每 10 真实回合 | N5 | 低 |
| 复核不得自证 | 裁决需双单元、不得自证 | B 阶段：提炼者与审核者分离 | B 阶段 |
| 公开基准 | hive-memory-bench | 小规模可复现评估 | Later |

## 明确不做

- 平台化（蜂群 / 编译器 / 并发引擎）：超出"人格层"定位
- Python / Rust 双运行时：破坏零依赖
- 30+ 工具面：默认只暴露 4 个动词
- 自建云服务

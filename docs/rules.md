# 项目通用规则（索引）

> 这份文件**只做索引**：一条规则一行，指向它的权威出处和它的检查手段。
> 规则本身写在权威文档里；这里再抄一遍就等于制造第二个版本。
> 权威来源：[process.md](process.md)（十步）、[checklist.md](checklist.md)（每次改动）、[code-quality.md](code-quality.md)、[ADR 0027](adr/0027-code-vs-model-boundary.md)。
> 想知道"现在做到哪"看 [state.md](state.md)；想知道"下次从哪继续"看 state.md 的「下次从这里继续」。

## 九、元规则（这套规则本身的规则）

1. **规则进记忆不等于会在决策点触发**——能机器查的就机器查（本文件第三列）。
2. **一条规则只有一个权威**：本文件是索引，发现重复就删掉弱的、留链接。
3. **规则也要被证伪**：样本不够就写"待验收"，不写"已完成"。
4. **新增规则要同时给出检查方式**；给不出检查方式的，标"人工 review"，不许假装自动。

## 十、适用范围：能不能直接用到新项目

**能搬的是形式，不能整套照搬的是内容。**判据只有一条：

> 一条规则要能搬，它必须能写成"规则 + 权威 + 检查"三元组；`权威` 和 `检查` 指向本仓库路径的，搬到新项目就得**重写这两格**，否则它只是一句愿望。

### 10.1 直接可搬（与项目无关）

| 组 | 为什么通用 |
|---|---|
| W1 十步、W2 四段交付 | 任何有"别人会读你改动"的项目 |
| W3 先红后绿、W4 空样本不是判决 | 任何有测试的项目 |
| U1 一件事一个表示、U2 定义单点声明、U4 假设入代码 | 中大型项目的通病 |
| F1 失败可区分于"没有"、F2 兜底掩盖根因 | 任何有错误处理的项目 |
| T1 改代码不用字符串替换、T2 改完看 diff | 任何用 shell 的项目 |
| P1 现状文档单一权威 + 时间戳、P2 地图只放链接 | 任何文档超过 10 份的项目 |
| R1 验证装上去的副本、R3 版本/tag/manifest 一致 | 任何要部署的项目 |
| 元规则 1–4 | 这套索引本身的方法 |

### 10.2 原则可搬，检查必须重写

| 组 | 新项目要替换的东西 |
|---|---|
| W5 模型环节四关 | 沿用判据；ADR 编号换成新项目的决策记录 |
| W6 先可观测 | 沿用；trace/日志字段是新的 |
| B1 语义归模型、B3 无默认值、B4 语法不推语义 | 沿用；`config/domains.ts`、`test/boundary.test.ts` 要按新项目重建 |
| B2 值域单一声明 | 沿用；`declarations.json` 换成新项目的登记表，health-check 要新写 |
| D2 不截断、按整单位取舍 | 沿用；具体单位（句/轮/条）由场景定 |
| P4 事故痕迹全量扫描 | 沿用；扫描器要针对新项目的语言重写 |

### 10.3 不可搬（本项目特有）

| 内容 | 为什么 |
|---|---|
| B6/B7 抽取与阶段输入契约 | 只有"模型读对话、代码落库"的系统才有这层 |
| D1/D3–D8 事实/线索/两层/三层 | 这是 soulbridge 的记忆模型，不是通用工程规则 |
| W4 的归属实验、D7 默认继续 | 依赖这个项目的失败模式（碎片化 vs 误合并） |
| 各 ADR 的具体数值（≥90%、>50%、≥5/10） | 是这批数据下定的线，换场景要重测 |

### 10.4 新项目起步最小集

不要一次搬 40 条。先立**三条能查的**，它们在任何项目里都能立刻抓到真事故：

```
1. 编码/替换损坏扫描（非 UTF-8、换行被写成字面量、行首残片）
2. 值域单一声明（关键枚举只有一处定义，库/配置里不得出现域外值）
3. 文档落后于代码（现状文档带时间戳，代码新于它即失败）
```

这三条落地之后，再按"三元组"逐条加——**每条都要同时给出检查和权威**，否则不进本文件。

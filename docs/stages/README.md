# 阶段（Stage）

> 路线图可以改，所以它不能当锚。锚是**阶段范围 + 完成定义**。

## 规则

1. **一个阶段一个文件**，开工前写，写清楚：**效果目标**、效果判据、预算、范围内、范围外。
   效果目标描述**产品达到了什么状态**（用户能感知的），不是功能清单。
   工程指标（不重复注入、失败率）只是**前提**，全绿也不等于阶段完成。
2. **范围内才做**。阶段中出现的新想法一律进"范围外"，不直接动手。
3. **要调入必须先调出**。想在新阶段加一项，就从范围内删掉一项等量的，并记录放弃了什么。
4. **预算用尽强制收口**。到期或版本数用完，写收尾记录，不管完成没有。
5. **修改阶段文件本身**需要一次明确的决定（在收尾或开工时），不能中途悄悄改。

## 判断是否偏离

不再问"这在路线图上吗"，而是问：

| 问题 | 答"不是"就意味着 |
|---|---|
| 它属于当前阶段范围内吗？ | 进范围外，或走 swap |
| 它推进当前完成定义吗？ | 它是范围外的事 |
| 它让本阶段预算超了吗？ | 必须收口或调出别项 |

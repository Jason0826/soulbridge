## 效果目标（一句话）

**连续用一周，我不需要重复解释同一件事；它会在合适的时候自己带上相关记忆。**

### 观察设计失败的具体原因

**一、判据 2 缺少可执行的抽查手段（设计缺陷，不是执行问题）**

判据要求"抽查 10 次相关提问"。但 `plugin.log` 只记 `prestep: inject turn=N chars=M`，
**不记注入的是哪几条**。175 次注入没有一次能回溯——"这条注入有没有帮我回答"
只能当场看，而观察期内没有人当场看。

这不是"忘了抽查"，是**日志里没有可供抽查的内容**。

**二、判据 3 的数据源精度不足**

`corrections` 28 条中，25 条是 `structural:negation` 的误判：

```
28 条里，真纠正 3 条：rule:不对 ×2、rule:错了 ×1
其余 25 条只是句子含"不/没/不是"的正常提问或陈述
   例：「咨询一下心理问题，如果你对一个女生有好感…」被判为纠正
```

精度 **3/28 ≈ 11%**。用它数"记岔几次"，数字不可信。

**三、判据 1 的时间尺度与使用模式不匹配**

判据 1 假设"日常重复"（发布窗口、编辑器偏好这类会被反复提醒的事）。
实际使用是**连续深度开发对话**——每个话题都是新的，3 天里没有可测的"同一事实重申"。

|---|---|

### 一句话结论

> **S1 既没有证明"记忆有用"，也没有证明"没用"。它证明的是：现在的观察方法测不出来。**

这个结论本身有价值——**它排除了"继续按原方式观察"这个选项**。

### 下一个阶段建议（按优先级）

1. **先修观察手段**（否则下个阶段仍然评估不了）
   - 注入日志记 `ids` + 每条字符数，让判据 2 可回溯抽查
   - 判据 3 只用 `rule:不对` / `rule:错了`，或收紧 `negation` 规则
2. **再定"一条记忆是什么"**（[briefs/0010](../briefs/0010-memory-unit.md)）
   - 条目无界（7 ~ 18202 字）是判据 2/3 都测不准的底层原因
3. **最后才谈功能**（B1 日常记忆、B4 情绪词表、0009 schema）

**不建议**在观察手段修好之前启动下一个"效果阶段"——否则会重复同样的失败。

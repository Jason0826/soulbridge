# ADR 0002：实现语言选 TypeScript

- 状态：Accepted
- 日期：2026-10-27
- 相关：ADR 0004（依赖策略）

## 背景

前身项目用 Rust 写成，作者读不动自己的代码——这是最硬的一条约束：**一个人维护不了自己看不进去的语言。**

同时要满足三件事：宿主侧集成（MCP、插件生态）、零配置分发（`npx` 一行）、可被陌生人读懂并提 PR。

## 备选

| 语言 | 优势 | 否决理由 |
|---|---|---|
| **Rust**（现状） | 运行时正确性最强 | 维护者读不动；贡献者门槛高；对 IO 密集场景没有收益 |
| **Go** | 单二进制、并发简单、易读 | 领域建模啰嗦（联合类型、不可变数据）；插件/MCP 生态弱于 TS |
| **Python** | 生态最全、迭代最快 | 类型系统弱，端口与协议契约靠自觉；分发必须带解释器 |
| **Kotlin / C#** | 分层与类型好 | CLI 启动慢、分发重，不适合旁挂进程 |
| **TypeScript** | 结构化类型天然适合端口；MCP 官方 SDK；`npx` 分发；Node 22.6+ 原生跑 `.ts` | —— |

## 决定

用 TypeScript，并附加三条硬约束：

1. `strict` + `erasableSyntaxOnly`（保证 Node 可直接执行，不需要构建步骤）
2. 公共 API 不出现 `any`
3. `core` 只用 Node 内置模块（见 ADR 0004）

## 后果

**正面**

- 装一个 Node 就能跑，没有构建管线；
- 判别联合把"消息 / 工具调用 / 决策"建模得很自然；
- `AbortSignal` + 事件循环天然适配"IO 密集的旁挂进程"。

**负面**

- 没有单二进制；启动约 100–300ms；
- 运行时类型安全弱于 Rust；
- 需要靠测试与 lint 补足编译期保证。

**缓解**

- 核心逻辑保持纯函数，用属性测试覆盖不变量；
- 所有 I/O 集中在 adapter，core 不做副作用（可测性优先于性能）。

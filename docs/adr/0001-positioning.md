# ADR 0001：只做 soul 层，不做 runtime

- 状态：Accepted
- 日期：2026-10-27
- 相关：RFC 0001、ADR 0007

## 背景

项目的前身 `soulkernel-rs` 同时包含 runtime（agent loop、工具集、TUI）与 soul 层（记忆、情绪、身份、反思）。运行一年后得到的判断是：

- runtime 是**商品**：Claude Code、Pi、DSH 免费提供，且比自建的更成熟；
- 竞争最激烈的记忆基础设施（Supermemory、Mem0）已经由团队化项目占据；
- 真正稀缺的是**跨宿主的人格连续性**，而这恰好没有任何一家会做（大厂不会给竞品做适配）。

## 备选

1. **全栈自研**：runtime + soul。控制力最强，但每年要追宿主的 API 演进，且护城河为零。
2. **只做库**：让宿主 import 我们的代码。耦合宿主语言与版本，实际只有自己写的 agent 能用。
3. **只做 soul 层，旁挂接入**：独立进程 / CLI，通过指令、transcript、hooks、MCP 与宿主协作。
4. **只做记忆 API**：直接和 Supermemory 正面竞争。

## 决定

选 3。项目边界：

- **在范围内**：人格状态、反思、注入策略、评估、宿主适配。
- **明确不做**：agent loop、工具执行、TUI、模型路由、内容检索引擎、云端服务。

## 后果

**正面**

- 代码量从 2.4 万行降到可维护的数千行；
- 可以接多个宿主，这是唯一的结构性差异；
- 不承担 runtime 的兼容性负担。

**负面**

- 失去对上下文的绝对控制：注入只是建议，宿主可能忽略或截断；
- 无法做严格 A/B（不能控制宿主 prompt），只能做观察性评估；
- 需要持续跟进 N 个宿主的 API 变化。

**需要持续验证**

- 若宿主平台原生提供跨工具的人格层，本项目就没有位置了（见 RFC 0001 的放弃条件）。

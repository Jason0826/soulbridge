# ADR 0015：分析器端口与模型适配器

- 状态：Accepted
- 日期：2026-10-28
- 关联：ADR 0016（规则预算）

## 背景

纯规则能识别"说了情绪词"的句子，识别不了四类情况：反讽（"太好了，又崩了"）、隐式（"行吧"/"随便"）、极简碎片（"……"）、语境依赖（"这破玩意"是对代码还是对人）。

引入小模型能覆盖这些，但与项目的三条约束冲突：零依赖、单轮 <5ms、可审计。

## 备选

1. 只做规则：最快最稳，天花板低。
2. 只做模型：覆盖好，破坏零依赖与延迟承诺。
3. **规则为默认 + 端口化 + 模型 opt-in**。
4. 让宿主代判（调用方把 affect 传进来）：零成本，但宿主未必配合，且信号不可审计。

## 决定

选 3。

```ts
interface AffectAnalyzer {
  readonly id: string;                       // 'lexicon' | 'llm' | …
  analyze(text: string): AffectSignal | Promise<AffectSignal>;
}
```

- 默认 `lexiconAnalyzer`（同步、纯函数）
- 可选 `createLlmAnalyzer()`：位于 CLI 包（允许 I/O），只用内置 `fetch`，**零 npm 依赖**
- 端点由 `SOULBRIDGE_AFFECT_LLM_URL` 配置（OpenAI 兼容或 Ollama），默认 `qwen3:1.7b`
- 超时 3s；超时/非 2xx/坏 JSON → **降级为规则**，`analyzer` 字段如实标注
- 模型输出的 confidence 上限压到 **0.85**，防止"模型很自信"直接穿透注入门槛
- 隐私：只发送当前这一条 user 文本，不发历史、不发记忆

## 后果

**正面**

- 想试模型的人改一个环境变量即可，不需要 fork
- 默认安装仍是零依赖、无网络
- 两个分析器共享同一个 `AffectSignal` 契约与同一套黄金集

**负面**

- 两条代码路径，需要防止行为漂移（用同一批测试与黄金集约束）
- 模型路径的延迟（100ms–1s）与 FAQ 里"<5ms"不符，文档必须分开表述

**切换默认的条件**

规则集达到上限（8 条）且 holdout 基础桶 < 90% 时，才允许把模型设为默认候选；由 ADR 0016 的停写触发决定。

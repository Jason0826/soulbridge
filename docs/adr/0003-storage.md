# ADR 0003：默认 SQLite，人格状态自研，内容记忆可外接

- 状态：Accepted
- 日期：2026-10-27
- 相关：ADR 0009（内容记忆 v0 不接）

## 背景

SoulKernel 的经验：把全部状态放进 PostgreSQL 带来了 RLS、角色管理与"没有数据库就退化成纯工具"的复杂度。开源项目若要求用户先起一个数据库，安装转化率会掉到接近零。

同时，记忆有两类，性质完全不同：

- **人格状态**（身份、情绪、策略、关系、特质）：几十到几百条，结构化，查询靠精确条件；
- **内容记忆**（对话片段、文档、代码库知识）：几万条，模糊检索，检索质量决定体验。

## 备选

1. 只支持 PostgreSQL：一致性好，安装门槛高。
2. 只支持 SQLite：简单，但团队/多人场景受限。
3. **SQLite 默认 + Postgres 可选**，且两类记忆走不同实现。
4. 完全交给外部服务（Supermemory / Mem0）：外包了检索，但把本体压平成"事实 + 文档"。

## 决定

选 3，并明确分界：

- **人格状态永远自研**：量小、语义精确、需要 `valid_from / superseded_by / status` 这类精确语义；
- **内容记忆留端口**，v0 不接任何外部服务（ADR 0009），检索先用关键词。

## 后果

**正面**

- `npx soulkit init` 即可用，数据落在一个文件里，备份=复制；
- 人格层不被外部服务的数据模型绑架；
- 未来接 Postgres / 外部记忆服务只需要一个 adapter。

**负面**

- SQLite 单写者：并发写要靠队列，不能多进程同时写；
- 迁移脚本必须手写、可重复执行；
- 多用户隔离在 v0 不做（本地单用户），后续要用 `user_id` 过滤 + 测试保证。

**需要持续验证**

- 若真实使用中"内容检索质量"成为主要抱怨，说明 v0 的取舍错了，应提前接外部记忆层。

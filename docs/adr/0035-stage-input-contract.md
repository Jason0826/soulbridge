# ADR 0035：各阶段的输入契约——整轮进去，来源不对称

- 状态：Proposed（写完先对一遍，再改代码）
- 日期：2026-11-03
- 关联：[0010 记忆单位](../briefs/0010-memory-unit.md)（"一条记忆 = 交流单元（用户 + 助手）"）、[0014 轮与步骤](../briefs/0014-turn-steps.md)、[0016 提取与归纳](../briefs/0016-extraction-consolidation.md)、[0017 主题线索](../briefs/0017-topic-threads.md)、[ADR 0032](0032-two-layers-of-memory.md)
- 由来：用户问"一个主题不应该是只有我的回答，没有进文档吗"，查证后发现**文档只规定了"存"的单位，没规定"读"的单位**

## 背景

0010 §4 把"必须"定得很清楚：

```
一条记忆 = 一个交流单元（用户 + 助手），不是单句
验收：写入一轮后，读出的条目同时含两侧
```

实现里，存储层符合（`turns` 存 `user_text` + `assistant_text` + steps），
但**读取层各自为政**：

| 阶段 | 实际读什么 | 符合 0010 |
|---|---|---|
| 记录 `turns` | 用户 + 助手 + steps | ✅ |
| 抽取 `runExtraction` | **只有 `turn.userText`** | ❌ |
| 归属 `applyThread` | 用户 + 助手（候选线索带近轮双方原文） | ✅ |
| 归纳 `renderConsolidationPrompt` | 整条线索双方 | ✅ |
| 交接 `renderHandoff` | **只写用户的话** | ❌ |

两处后果可观测：

1. 抽取 prompt 的 `<when-to-write>` 第 4 类是"**我给出的承诺**（'我明天把表补上'）"，
   而输入里从来没有助手的话——**这条规则在实现上不可能命中**（死规则）。
2. 数据：`holder=self` 的教训/原则 16 条，**带来源轮的 0 条**，全部来自
   `soul_remember` 工具与旧记忆迁移。抽取从未产出过关于"我自己"的事实。

所以"助手的话要不要被抽取"不是口味问题，是**已写下的需求没有落到读取侧**。

## 决策

### 1. 单位：整轮，双方

```
一轮（turn）= 用户的话 + 我的回复（+ 步骤仅作记录，不进证据）
```

除存储外，**抽取、归属、归纳、交接的输入单位都是整轮**。
不引入"助手侧单独一套规则"。

> **修订（2026-11-04，[0025](../briefs/0025-thread-extraction.md)）**：抽取的输入单位升级为
> **整条线索（该线索的全部轮次，按时间排列）**——因为一个主题里的对话要合起来理解，
> 单轮抽出的句子会缺主语（实测 33 条）。本文余下契约仍然成立：“整轮、双方”是抽取输入的
> **原子**，线索是这些原子的有序集合；归属/归纳/交接的单位不变。

### 2. 规则：一套，对双方同样适用

`<when-to-write>` 的四类与噪声清单不区分说话人：

| 抽什么 | 用户说 | 我说 |
|---|---|---|
| 世界发生了什么 | ✅ | ✅（如"我查了日志，是 401"） |
| 某人的状态/偏好/判断 | ✅ | ✅ |
| 承诺 | ✅ | ✅（此前不可达） |
| **不抽**：寒暄、提问、催促、自我介绍、能力说明 | ❌ | ❌ |

### 3. 不对称只在来源与证据，不在规则

| 来源 | `source` | `confidence` | 额外要求 |
|---|---|---|---|
| 用户的话 | `told` / `experienced` | 按抽取给出的 | 无 |
| 我的话（陈述世界） | `inferred` | 比同置信的用户话低一档 | **必须带证据槽位**（轮次 id / 工具结果 / 测试输出） |
| 我的话（承诺/决定） | `inferred`，`type_name=承诺` / `决定`，`holder=self` | 同上 | 同上；未兑现时开缺口而非改写 |
| 我的自述（"我改好了""我记住了"） | `inferred` | — | **无证据不写**；最多进候选（待 R3 的候选态） |

判据一句话：**谁说的只影响可信度标签，不影响能不能抽。**

### 4. 交接（handoff）包含双方

"上次说到哪"包含"我上次说到哪"：闭合线索的末 1–2 轮，用户与我的回复都写。

## 后果

**接受的**

- 事实数会上升：我的承诺、决定、判断首次进入记忆。
- 可能出现"自我对话噪声"（我复述、我总结）。对策是上面的证据要求，不是把助手的话排除掉。

**必须同时做的**

- `source` 字段要有真实语义：目前 `inferred` 几乎不用，改完后它是"我自己说的"的默认。
- 证据槽位（`依据`）需要成为 claim 类事实的硬要求；缺失时降级为普通事实并计数。
- 观测：`自述事实数`、`带证据比例`、`无证据被拒数`，写进 trace，不靠感觉。

## 验收（可证伪）

| # | 场景 | 期望 |
|---|---|---|
| 1 | 我的回复里说"我明天把表补上" | 产出一条 `承诺` 事实：`holder=self`、`source=inferred`、带 `依据=<本轮 id>` |
| 2 | 我说的"我查了日志发现是 401" | 产出事实，`source=inferred`，带依据 |
| 3 | 我的自我介绍"我是小灵，一个持续成长的伙伴" | **不产出任何事实** |
| 4 | 你的话 | 行为不变（`source=told/experienced`，无额外证据要求） |
| 5 | handoff | 闭合线索的块里同时有"用户：…"和"我：…" |
| 6 | 一节线索归纳 | 证据可追到双方轮次 |

## 不做什么

- 不把 reasoning/思考过程当证据（它是草稿，只记录不引用）。
- 不为助手侧新增提示词条目——四类规则已经存在，缺的是输入。
- 不在本 ADR 里引入候选态（R3 的事）；无证据的自我主张先按普通事实落库并计数。

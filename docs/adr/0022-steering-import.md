# ADR 0022：steering 文件导入

- 状态：Accepted
- 日期：2026-10-28
- 关联：ADR 0019（与 steering 文件的边界）

## 背景

ADR 0019 的结论是：不替代 `AGENTS.md`，但可以把它**读进来**。用户已经写好的约定不该要求他们重写一遍。

难点在"读多少"：一份 300 行的 `AGENTS.md` 里有标题、代码块、表格、徽章、链接、以及真正的约定。全导进来是噪音，一行不导又没有价值。

## 备选

1. 全文导入成一条记忆：简单，但回忆时只能整段塞进去。
2. **按行抽取陈述句**：保守，但每条都可独立召回。
3. 用模型摘要：效果好，但引入模型依赖与不确定性。

## 决定

选 2，规则写死：

| 抽取 | 跳过 |
|---|---|
| 列表项（`-` / `*` / `1.` / `- [x]`），≥8 字 | 标题、围栏代码块、表格行、徽章、纯链接 |
| 独立段落，≥12 字且以句末标点结尾 | 短于阈值的行、分隔线 |

**分类**（优先级从上到下）：

1. 含「我喜欢/偏好/习惯/prefer」→ `trait`（importance 6）
2. 含「必须/禁止/不要/每次/must/never」→ `strategy`（importance 8）
3. 含「项目/仓库/使用/技术栈」→ `fact`（6）
4. 其他 → `fact`（5）

**去重**：`normalizeForDedupe`（小写、去掉空白与标点）后比对已有记忆，重复的跳过。

**上限**：单文件最多 200 条。

## 命令

```bash
soulbridge import --from AGENTS.md --dry-run   # 先看会导入多少
soulbridge import --from AGENTS.md
```

输出：`{ parsed, written, skipped }`。

## 后果

**正面**

- 用户已有的约定零成本迁移
- 每条独立可召回，不是一整块文本
- `--dry-run` 让导入可预览、可拒绝

**负面**

- 只能抽取"像约定的句子"，散落在段落里的规则会漏
- 分类是启发式的，会错（例如"必须"出现在偏好句里——已用优先级缓解）
- 不处理英文长段落（阈值更严）

**不做**

- 不写回 steering 文件（单向导入）
- 不监听文件变化（没有守护进程）
- 不导入代码块内容

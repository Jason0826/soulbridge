# ADR 0004：core 零运行时依赖

- 状态：Accepted
- 日期：2026-10-27
- 相关：ADR 0002、ADR 0011（质量门禁）

## 背景

开源项目的信任成本主要来自两处：装不上、看不完。依赖越多，两者都越糟。

而本项目的核心能力（分词、打分、注入拼装、反思规则）**不需要任何第三方库**——需要的只是字符串处理与 SQL，Node 内置已足够。

## 备选

1. 允许常用库（zod、better-sqlite3、jieba 等）：开发快，但引入原生编译与体积问题。
2. 零依赖，全部手写：可读、可审计、`npm i` 都不需要。
3. 仅依赖类型库：收益小。

## 决定

选 2，规则如下：

- `packages/core`：只允许 `node:` 内置模块；
- `packages/cli`：同样零依赖；
- **adapter 可以带依赖**（宿主的 SDK 不可控），但必须在各自的 `package.json` 里声明；
- 数据库用 `node:sqlite`（Node 22.5+ 内置，实验性但可用）。

## 后果

**正面**

- 供应链风险接近零，代码审查面小；
- 离线可用，内网/受限环境友好；
- 任何贡献者都能在十分钟内读完 core。

**负面**

- 分词只能用最大正向匹配，不能上 jieba / HanLP；
- HTTP、schema 校验、日志都要自己写薄薄一层；
- `node:sqlite` 仍是实验特性，API 可能变（用适配层隔离，出问题只改一个文件）。

**红线**

- 任何新增依赖的 PR，必须先在 ADR 里论证"为什么手写代价更大"。

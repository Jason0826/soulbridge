# ADR 0031：模型依赖的验收边界

- 状态：Accepted
- 日期：2026-11-02
- 关联：[ADR 0027](0027-code-vs-model-boundary.md)（语义归模型，结构归代码）、[ADR 0029](0029-extraction-is-the-models-job.md)（抽取是模型的活，规则做地板）、[ADR 0030](0030-core-adapter-boundary.md)

## 背景

用户提出一个尖锐的问题：

> 很多核心都靠 prompt 实现，而 prompt 本身就是一种 hope。可做可不做的事情，如果基于 hope 做事，我们还有价值吗？

这个担心成立，而且今天有三次现场证据：

| 事 | 当时的依赖 | 结果 |
|---|---|---|
| 要求模型输出合法 JSON | 纯 hope | 失败；一个括号让整批作废，54 字符被丢，查了两小时 |
| 改成填表 + 逐行解析 | **代码兜底** | 成立；模型回一个字「无」也能正确解析 |
| 结论只有一条证据 | **代码闸门** | 被拦下，没有污染结论层 |

差别不在"用不用模型"，而在**有没有能自己判定对错的验收层**。

## 决策

### 1. 价值主张不建立在"模型做对"上

模型是**生产者**，代码是**验收官与账本**。

| 资产 | 谁保证 | 换模型后 |
|---|---|---|
| 不丢（每轮原文与步骤） | 代码，确定性写入 | 在 |
| 可查（事实能追到轮次） | 代码，外键 | 在 |
| 可改（错了标记失效） | 代码，supersede | 在 |
| 可带走（导出契约） | 代码，JSONL | 在 |

换模型只影响"新写进来的质量"，不影响"已经记下的东西"。

### 2. 每个模型环节必须凑齐四件套

```
1. 闸门 gate      确定性检查；不通过就不写，并记录原因
2. 地板 floor     模型不可用/失败时退到什么（规则、词典、或不写）
3. 度量 metric    一个比率，能看出它在退步
4. 可逆 reversal  错了能修（标记失效、人工纠正），不是只能删库
```

**答不全的环节，不允许进入主干。** 只准作为实验开关存在，且默认关闭。

### 3. 有些事永远不交给模型

| 必须由代码保证 | 原因 |
|---|---|
| 数据不丢、顺序正确 | 模型无法承诺 |
| 同一条事实不重复存 | 需要唯一性，不是语义 |
| 时间换算、排序、窗口 | 算术 |
| 谁能读到什么 | 授权 |
| 幂等（重复调用不产生重复写入） | 需要 id |

模型只在"语义判断"上出现：这段值不值得记、这条属于哪个话题、这两条能否归纳成一条、用户在不在表达情绪。

### 4. 现状盘点（2026-11-02）

| 环节 | 闸门 | 地板 | 度量 | 可逆 |
|---|---|---|---|---|
| 事实抽取 | ✅ 结构校验 + 槽位/时间 | ✅ 规则 | ⚠️ 有日志，无比率 | ✅ supersede |
| 结论归纳 | ✅ ≥2 证据 + 存在性 + 过概括 | ✅ 不写 | ⚠️ 有日志，无比率 | ✅ supersede |
| 线索归属 | ✅ id 必须存在且未关闭 | ✅ 开新 | ❌ 无 | ⚠️ 只能合并 |
| 情绪判断 | ⚠️ 数值 clamp | ✅ 词典 | ❌ 无 | ❌ |

**结论：四个环节全部缺"度量"，两个缺"可逆"。** 这正是"做没做对只能靠感觉"的原因。

## 度量定义（按环节）

| 环节 | 比率 | 计算方式 | 初版通过线 |
|---|---|---|---|
| 事实抽取 | 每轮事实数 | facts / turn | ≤1.5，且无"用户要求 X"类 |
| 结论归纳 | 支持率 | `consolidate ok` / (ok + dropped) | ≥80% |
| 线索归属 | 新线索率 | created / 总归属 | 观察值，暂无阈值 |
| 线索归属 | 单线索连续率 | continue / 总归属 | 观察值，暂无阈值 |
| 情绪 | 非零率 | 有效样本 / 全部样本 | ≥50%（低于说明读不出） |

**初版通过线只是起点**——先有数，再定线。

## 后果

1. 新功能若含模型环节，PR/设计必须先填四件套，否则不做。
2. 每次发版前跑一次度量脚本，把比率写进发布记录。
3. 线索归属与情绪两个环节**先补度量**，再谈优化。
4. 声明中"模型可替换"成为可验证承诺：换 provider 后四件套仍成立，度量不塌。

## 反面清单（以下写法不允许）

- 用 prompt 约束一个**必须成立**的事实（"请确保不重复"）——重复由唯一索引保证。
- 模型失败后**静默继续**（无 floor、无日志）。
- 只记"成功/失败"，不记**比率**。
- 错了只能删库重来，没有 supersede 路径。

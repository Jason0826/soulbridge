# ADR 0032：两层记忆——世界与人物

- 状态：Accepted
- 日期：2026-11-02
- 关联：[ADR 0027](0027-code-vs-model-boundary.md)（语义归模型，结构归代码）、[ADR 0029](0029-extraction-is-the-models-job.md)、[0019](../briefs/0019-memory-selection.md)、[0020](../briefs/0020-retrieval-funnel.md)

## 背景

一次实测暴露了根因：库里 26 条事实，**`holder` 全是 `world`（0 条人物层），77% 没有时间**。同时 `type_name` 分裂成 16 种标签，其中"观点 / 原则 / 设计原则 / 想法 / 判断依据 / 问题观察"六种都在说同一类事。

我们一直在用**词汇**（type_name）去区分两类东西：

```
世界发生了什么     吃饭、验证、约定
这个人怎么想       偏好、观点、原则
```

但**结构里早就有 `holder` 和 `at` 两个字段**来做这件事，却从来没被使用。词汇补丁越打越多，是因为结构没被承认。

## 决策

### 1. `holder` 是结构，不是默认值

| holder | 含义 | 例子 |
|---|---|---|
| `world` | 在世界里成立 | 用户与 a 吃了火锅 |
| `<entity_id>` | 在某个人的心里成立 | 用户认为改 prompt 没用 |

**代码靠它决定走哪套规则**，不靠 `type_name`。

### 2. 世界层：必须可定位

一条世界事实要有**定位**，定位 = `at` 或 `at_text`，并标记精度：

```
day       2026-11-01
range     上周 / 上个月
relative  初次见面的时候 / 上次
unknown   说得出存在，但说不出时间
```

**`unknown` 也允许入库**，因为它仍然是事实；不允许的是**假装精确**。

任何事实都还有一个永远可用的下界：

```
recorded_at  它被说出来的时间（宿主给的，必有）
```

所以“不知道日期” ≠ “没有时间”。排序用 `at ?? recorded_at`。

### 3. 人物层：没有事件时间，可被推翻

```
holder = 那个人
at     = 空（或有效期，暂不实现）
作用   作为画像的证据，不直接当世界事实
```

“用户讨厌反复交代”不是某天发生的事，是他的一个倾向；它会被后来的事推翻（supersede），不会被“删除”。

### 4. `type_name` 降级为描述

它继续存在、继续由模型自由填写，**但代码不再依赖它做任何路由**。今天 16 种标签的碎片化，从此不是问题：它们只是描述。

### 5. 检索按层，不按词

| 问句 | 层 | 取法 |
|---|---|---|
| 上次和 a 吃饭 | 世界 | 实体 a + 有定位 + 谓词/相关度 |
| 你讨厌什么 | 人物 | holder = 用户 |
| 她最近怎么样 | 两层 | 她的事件 + 她的倾向 |
| 上次聊到哪 | 对话 | 上一闭合线索 |

### 6. 时间未知：开缺口，不打断

**不在抽取时追问时间**——那会把聊天变成填表。做法是：

```
写入   时间未知 → 标 unknown，同时开一个缺口："那次吃饭是什么时候"
提问   在被问到且 unknown 时，承认"不确定"并可反问
不问   不为填字段打断对话
```

这补上了缺口的第五个来源：**确定发生、但时间不明**。

## 三条硬规则

1. **不确定是否发生 → 不写**（原有规则：推测永不记）。
2. **确定发生但时间不明 → 写，标 `unknown`，开缺口。** 不得丢弃。
3. **不得把 `unknown` 当精确时间用**——回答“什么时候”时必须说明不确定。

## 与"时间是否必要"的关系

用户的判断是对的：**时间对世界层是必要的**。但必要的是**可定位**，不是精确日期。

反例就在我们自己的库里：那条"和 a 吃火锅"没有日期。按“无时间即不成立”处理，它当初就不该入库，今天问“上次和 a 吃饭”就永远没有答案。**丢弃真实记忆比不确定的日期更糟。**

## 后果

| 影响面 | 变化 |
|---|---|
| 抽取 prompt | 输出要区分“世界事实（时间 + 参与者）”与“某人的看法（holder=那个人）” |
| 写入闸门 | world 事实必须有定位或 `unknown`；人物事实必须有 holder 实体 |
| 检索 | 路由按 `holder` 选层，不再按 `type_name` |
| 归纳 | 人物层是画像的证据；世界层是事件的证据，两者的归纳规则不同 |
| 历史数据 | 26 条旧事实 `holder` 全是 world，需要一次离线重分类（延后，不阻塞） |

## 验收

| # | 用例 | 期望 |
|---|---|---|
| 1 | 同一批 26 句重跑抽取 | 世界层 100% 有定位或 `unknown`；人物层 holder≠world 且无事件时间 |
| 2 | 上次和 a 吃饭 | 仍能取到，且不越主体 |
| 3 | 你讨厌什么 | 返回人物层事实，不混入世界事件 |
| 4 | 时间未知的火锅 | 能被写出、能被召回，回答时说“不确定日期” |

## 开放问题

| 问题 | 现状 |
|---|---|
| 相对时间归一（"初次见面" → 锚点事件） | 需要先有那个事件；暂存原文 |
| 共同约定属于谁（我方和他方心里都成立） | 暂按世界层 + 双方参与者 |
| 人物层要不要有效期 | 暂不需要，等“他变了”成为真实需求 |

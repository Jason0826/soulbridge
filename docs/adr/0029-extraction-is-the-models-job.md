# ADR 0029：抽取归模型，规则只做兜底与预筛

- 状态：Accepted
- 日期：2026-11-01
- 关联：[ADR 0027](0027-code-vs-model-boundary.md)（语义归模型）、[0015 读书验证](../briefs/0015-book-recall.md)、[model.v0](../spec/model.v0.md)

## 背景

我先实现了"规则先跑、模型兜底"的抽取器。用户指出：**代码做抽取效果不会好，模型做提取、代码做兜底**——并要求先看同类项目怎么做。

查证结果一致：

| 项目 | 抽取方式 |
|---|---|
| **Generative Agents**（Park et al. 2023） | 观察写成自然语言，**LLM 打分 poignancy**，反思由 LLM 合成（[架构说明](https://raw.githubusercontent.com/agentpatterns-ai/website/refs/heads/main/patterns/agent-design/generative-agents-memory-stream.md)） |
| **Mem0** | LLM 抽记忆，再由 LLM 决定 **ADD / UPDATE / DELETE / NOOP**（[相关 PR](https://github.com/mem0ai/mem0/pull/4965)） |
| **Graphiti** | LLM 从 episode 抽实体与事实边，带**双时间有效期**（[系统说明](https://github.com/neoneye/agent-memory-atlas/blob/0eb6f6115095e53e0fc0530c48f451bcaf8c05aa/content/systems/graphiti.md)） |

**没有一个用规则抽结构。** 规则的失败不是"覆盖不够"，是**方向错了**：中文句法、指代、隐含关系都不是确定性规则能吃的。

## 决定

**默认顺序：模型抽取 → 代码校验 → 代码提交。**

规则保留三件事，都不是"抽取"：

| 用途 | 说明 |
|---|---|
| **离线兜底** | 没有配置模型时仍能工作（降级不失效） |
| **预筛** | 少于 4 个字的文本不调模型（"好的"不产生事实） |
| **交叉检查** | 模型答案为空/失败时回落到规则，不丢这一轮 |

代码的职责不变（ADR 0027）：**校验、去重、实体合并、写库**。所有模型输出都当草案，走 `commitDrafts` 的闸门。

## 分工表（更新）

| 环节 | 谁做 |
|---|---|
| 读出一句话里有什么人、什么事、什么槽位 | **模型** |
| 规格化（时间表达、来源、置信） | 模型给，代码校验 |
| 结构校验（字段、类型、越界） | 代码 |
| 实体合并与去重 | 代码 |
| 拒绝与记录原因 | 代码 |
| 存储与取数 | 代码 |

## 补充：模型要看到上下文，输出合并操作

只让模型"抽事实"是不够的——它不知道库里已经有什么，就会造出重复实体，也看不出新信息与旧事实冲突。所以第二轮升级：

**输入**：已有实体（名字/别名/关系）、最近 12 条事实（带 id）、上一轮用户消息。
**输出**：操作而不是裸事实。

| 操作 | 含义 | 代码执行 |
|---|---|---|
| `add` | 新信息 | 写一条事实 |
| `supersede` | 与已知事实冲突，旧作废 | 写新事实 + 旧事实 `status=superseded`、`superseded_by=新id` |
| `update` | 修正/补充已知事实 | 同上 |
| `noop` | 没有值得记的 | 不写 |

两条保护：

- **目标必须存在**：`supersede/update` 的 target 必须是模型**看到过**的 id，否则降级为 `add`——宁可多记一条，也不能让它退休一条没读过的记忆。
- **空操作不算失败**：全是 `noop` 时返回"没有可用输出"，走兜底。

这就是 Mem0 的 ADD/UPDATE/DELETE 与 Graphiti 的失效边，落到我们模型上的形态。

## 后果

**正面**

- 抽取质量交给模型，换更强模型直接变好（符合 thesis）
- 规则退到兜底，维护成本下降
- "模型失败不丢轮次"这条有测试保证

**负面**

- 每轮多一次调用（预筛兜住一部分）
- 抽取 prompt 要长期维护，且是"隐性 schema"
- 模型可能编槽位，必须靠闸门与后续事实校验兜

## 验收

1. **读书测试**（brief 0015）用模型抽取跑一遍；同一批段落再跑规则版做 A/B
2. 指标看：实体 recall、事实 recall、**编造率**（规则版拿不到的槽位是不是真需要）
3. 若规则版在 recall 上不差，说明该书语料过于模板化——换一本书再测

## 不做的

- 不写分词/句法分析/指代消解等传统 NLP 规则
- 不让模型直接写库（必须过闸门）
- 不用规则去"纠正"模型输出（只在模型失败时兜底）

# ADR 0036：使用者判据层——工程绿灯回答不了"伴答得对不对"

- 状态：Proposed（写完先对一遍，Accepted 同批接线）
- 日期：2026-11-18
- 关联：[debt #9](../debt.md)（本 ADR 是它的 B 步）· [stages/s1-dsh-memory.md 可算口径](../stages/s1-dsh-memory.md)（**口径唯一处**：C1–C4 已落地，C5/C6 行随本 ADR 进表）· [ADR 0031](0031-model-dependency-acceptance.md)（工程三线，本文不动）· [ADR 0034](0034-attribution-defaults-to-continue.md)（"每 10 关闭 ≥5 结论"的出处）· [briefs/0030 §9](../briefs/0030-situated-disposition.md)（先测基线的教训）· [quality.md 4.1](../quality.md)（设计四问）
- 由来：11-16 用户问"从使用者角度，你觉得这个项目足够好吗" → 归因**判据体系缺一层** → 立 debt #9 → 用户拍「顺序来」A → B → A 落地（`413bf56`，11-17：C1–C4 口径 + quality.mjs S1 行 + `--s1-sample`）→ 本 ADR = B。第五、六条选题 11-18 拍定：**语气 + 主动洞察**（使用者痛感排序前两名，此前无任何红线归属）。

## 背景

现有全部门禁回答的都是"机制对不对"：

```
quality 三线（密度 / 支持率 / 情绪占比）→ 记忆的健康度
health-check                            → 仓库的健康度
观察点（sup/add、排序、预算组）          → 机制的正确性
```

没有一条回答"**伴答得对不对、接得自然不自然**"。后果是结构性的：使用者痛感前两名——**语气**（情绪非零率 2.6%，词典地板）与**主动洞察**（243 条关闭线索只出 25 条结论，每 10 关闭 1.03 条）——不触碰任何红线，于是永远排不上优先级。

S1 的四条效果判据本来就是使用者判据，但 10-31 收尾证明：观察设计不产生可用数据，就只能提前收口。A 步（`413bf56`）把它们救活——口径钉进 [s1-dsh-memory.md](../stages/s1-dsh-memory.md)「可算口径」，quality.mjs 出机器能出的那半。**本 ADR 把这个做法立成常设层，并补第五、六条。**

## 决策

### 1. 两层判据常设，进层四件齐

```
工程判据（机制对不对）   quality 三线 / health-check / 观察点 —— 0031 与各机制 ADR 管
使用者判据（伴好不好用） S1 C1–C6                     —— 本 ADR 管
```

新效果判据要进使用者层，**四件缺一不进**：

| # | 件 | 没有它的样子 |
|---|---|---|
| ① | 口径表行（分子 / 分母 / 数据源 / 通过线 / **谁判**）在 s1-dsh-memory.md | 口径在口头，两周后没人说得出分母是什么 |
| ② | 接线（quality.mjs S1 节出读数） | 算不出来 = 永远不会被看到 |
| ③ | 人判流程（机器出候选与样本，判决落 state.md） | 永远"待验收"——S1 第一次收尾的死因 |
| ④ | 通过线——或显式写"先测基线" | 没基线定线 = 第一天注定 FAIL（0030 §9 自己开的一枪） |

**C5/C6 在本 ADR Accepted、四件同批完成时才算进层**；Proposed 期间口径行先标 Proposed 进表。

### 2. 第五条 C5「语气接得上」

口径行在 [s1-dsh-memory.md](../stages/s1-dsh-memory.md) C5 行（唯一定义处），本 ADR 只定三件取舍：

- **候选双源**：`affect_samples.payload.hits` ∪ `user_text` 命中情绪标记词——词表从 `packages/core/src/affect/lexicon.ts` 解析（term-audit 同款读法），**不另抄一份**。词典候选稀疏（近 7 天 90 条里只有 2 条带 hits），所以标记词补召回。
- **三类判定**（人判按此）：接住 = 回应涉及情绪本身（承认 / 共情 / 顺着处境说）；没接住 = 直接办事 / 转移 / 无视；不适用 = 候选假阳性，**不入分母**。
- **不依赖 debt #5 解冻**：词典地板影响的只是机器侧候选召回，人读得出情绪——C5 可以先跑，情绪解冻仍按 debt #5 独立推进。

### 3. 第六条 C6「主动洞察」

两段各管一半，口径行在 s1-dsh-memory.md C6 行：

- **C6a 归纳产出率**（机器）：线 **≥5/10 沿用 0034，不新造**——这行一直在 0034 的验收表里，只是从没进过 quality.mjs，本层收编。现值 243 关闭 / 25 结论 = **1.03**。
- **C6b 结论被用上**：注入含结论 id 的次数（机器计数 → 观察值）+ 对话中主动引用结论（人判 → 先测基线）。存在但没被说出，不算"洞察"。

### 4. 接线顺序（Accepted 同批，全在 scripts/ 与 docs/，不碰 packages/core 运行时）

```
第一步  C6a 读数（纯机器，约 10 行 SQL——先做，当天见数）
第二步  C5 候选 + --c5-sample（lexicon 解析 + 标记词）
第三步  C6b 注入带结论计数
每步    quality.mjs 跑通 + health-check 0 FAIL + 读数进 state.md 条目
```

### 5. 判决落点

同 C1–C4：quality.mjs S1 节出读数，**人判结果记 state.md 当日条目**；空样本写"待验收"（规则 20）。

## 四问（[quality.md 4.1](../quality.md)）

| # | 问 | 答 |
|---|---|---|
| 1 | 何时可以实施 | 用户对完本 ADR（Proposed → Accepted）当天 |
| 2 | 怎么实施 | 决策 4 的三步；只动 scripts/ 与 docs/ |
| 3 | 如何验证 | 见验收表 |
| 4 | 有没有消费者 | 你（每周看 S1 节读数）+ debt #9 的收尾判决 |

## 后果

**接受的**

- C5/C6 初期读数必然是"基线未定"或 FAIL——这是"先有数再定线"的正常态，不是事故。
- 人判有持续成本：C5 每次抽查几分钟；换来的是唯一能回答"语气对不对"的通路。

**必须同时做的**

- 情绪标记词表**只进测量脚本**，不进运行时（测量工具边界，同 0035 审计口径）。
- 判决不落 state.md 就等于没跑——③ 是四件里最容易被省掉的。

## 验收（可证伪）

| # | 场景 | 期望 |
|---|---|---|
| 1 | 读口径表 | s1-dsh-memory.md 出现 C5/C6 行，含谁判与分母定义 |
| 2 | 跑 quality.mjs | C6a 打印 ≈1.03 vs 线 ≥5 → FAIL 可见（这是债的读数，不是回归） |
| 3 | 跑 `--c5-sample` | 出 10 个候选轮，人判跑出**首个基线数**——不再"永远待验收" |
| 4 | 评下一个效果判据 | 四件不齐 → 拒收（人工 review，规则 26） |
| 5 | 不越界 | 0031 三线、情绪冻结、0034 各指标读数不因本 ADR 改变 |

## 不做什么

- **不解冻 debt #5**（词典地板与 llm 分析器独立推进）。
- **不改 ADR 0031 的工程三线**与 quality.mjs 现有行。
- **不做自动语义判定**："接没接住""有没有主动引用"归人判，机器只出候选、样本、计数。
- **不给 C1–C4 造第二套口径**（唯一口径处仍是 s1-dsh-memory.md）。
- **不新增 role / 表 / 字段**——本层只加读数与流程。

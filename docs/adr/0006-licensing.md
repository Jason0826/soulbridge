# ADR 0006：许可证选 Apache-2.0

- 状态：Accepted
- 日期：2026-10-27
- 相关：ADR 0007（集成）、未来的 affect 词库 ADR

## 背景

目标是被**其他 agent 项目集成**，而不是被"防着用"。许可证直接决定两件事：企业法务能不能过、插件生态愿不愿意接。

## 备选

| 许可 | 优点 | 缺点 |
|---|---|---|
| MIT | 最简单、最流行 | 无专利授权条款，企业法务偶尔会挑 |
| **Apache-2.0** | 有明确专利授权 + 变更声明义务 | 文本更长，需要 NOTICE |
| AGPL-3.0 | 强制回馈 | 插件生态普遍回避，等于放弃集成 |
| BSL / 商业许可 | 可变现 | 与"被集成"目标冲突 |

## 决定

选 **Apache-2.0**。

附加规则：

- 仓库根放完整 `LICENSE` 与 `NOTICE`；
- 每个源文件不强制加版权头（降低贡献摩擦），但 `NOTICE` 里列明第三方来源；
- **不引入 GPL/AGPL 代码**（会传染整个项目）；
- 词库类数据必须单独核查来源许可——结构可以借鉴，词表不能想当然（见后续 affect 相关 ADR）。

## 后果

**正面**

- 企业采用阻力最小；
- 专利授权对贡献者也是保护。

**负面**

- 不能阻止别人拿去做闭源 SaaS；
- 需要在每次引入第三方资产时做许可核查（成本虽小但持续）。

**待办**

- 发布前必须补齐完整 `LICENSE` 文本（当前 README 已标注为 P0）。

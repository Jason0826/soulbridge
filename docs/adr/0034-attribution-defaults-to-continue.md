# ADR 0034：归属默认继续——碎片化比误合更贵

- 状态：Proposed（等实现验证后转 Accepted）
- 日期：2026-11-03
- 关联：[0017 主题线索](../briefs/0017-topic-threads.md)（本 ADR **修订**它的 §3 取舍与 §4.2 默认值，不改数据模型）、[0016 提取与归纳](../briefs/0016-extraction-consolidation.md)、[ADR 0031](0031-model-dependency-acceptance.md)
- 由来：用户问"这个抽取是每轮吗，我记得之前改成了按主题抽取"——查证时发现按主题的是归纳，而**线索根本没有形成**
- **修订（2026-11-05）**：归属**时机**由 [0028 离开点抽取](../briefs/0028-departure-flush.md) 取代——从每轮抽取顺带归属，改为**段抽取的输出**（段内多话题由模型一次切开）。本 ADR 的默认策略（fallback-previous、碎片比误合贵）与 join_reason 可审计**不变**。
- **修订（2026-11-06，0028 ⑤）**：上一条里"届时改为段级"已落地——验收指标口径改段级，见 §验收 的修订块（原表保留作历史口径），实现同批改 `scripts/attribution-stats.mjs`。

## 背景

0017 定了一个保守取舍：

```
错开新线索 → 话题碎，但结论仍然正确
错接到旧线索 → 两件事混成一条结论（污染）
所以：不确定就开新的
```

这个取舍当时是**推理**，没有数据。现在有了，而且结论相反。

实测（2026-11-03 09:50，297 轮 / 123 条线索）：

```
线索 123 条
  1 轮 = 103      2 轮 = 7      3 轮 = 1      4 轮 = 1      0 轮 = 11（孤儿）
每条线索的事实数
  0 条 = 104      1 条 = 15      2 条 = 4      ≥3 条 = 0
轮次归属
  171 / 297 轮没有线索（58%）
  已归属的 126 轮摊在 123 条线索上 → 1.02 轮/条
归纳产出
  关闭线索 112 条 → 结论 2 条
```

**归纳的门槛是"线索里 ≥2 条事实"。全库只有 4 条线索够格，没有一条到 3 条。**

于是：

| 0017 的假设 | 实测 |
|---|---|
| 碎片化只是"话题碎一点" | 碎片化 = **理解层永远没有输入**：123 条线索里 104 条零事实 |
| 误合会污染结论 | 误合会产生一条偏的结论，但它**可被后续事实推翻**（supersede 链在） |
| 不确定就开新是安全的 | 安全的是"不产生错误结论"，代价是**不产生任何结论** |

**碎片化的代价不是"结论错"，是"没有结论"。** 这比误合严重：系统看起来在记忆，实际不产生任何理解。

## 决策

**把默认反过来：不确定时接到最接近的旧线索，只有明确转折才开新。**

### 1. 判据

```
继续（默认）：
  上一轮属于某条线索，且这一轮没有出现转折信号
开新（需要证据）：
  · 显式转折："另外 / 换个话题 / 说回 / 不聊这个了 / 这事定了"
  · 与候选的主题词集合完全不重叠，且没有共同实体
  · 候选线索已闭合
不确定：
  选最近一条开放线索，**不是**开新
```

### 2. 模型看到的候选变实

0017 只给 `id | 主题 | 几轮前`，模型无法判断"这一轮是不是接着聊"，只能抓关键词。改为给出**近几轮原文**（截断）：

```
<open-threads>
  t_ab12 | 记忆分三层怎么落地 | 2 轮前
    用户：事实和结论要不要分表
    我：分，结论带证据
  t_cd34 | cookie 为什么失效 | 1 轮前
    用户：为什么带上 cookie 还是 401
</open-threads>
```

代价：每轮多约 100–200 字符的 prompt；收益：模型判断"是否继续"有了依据。

### 3. 上一轮用户文本成为必需输入

`ExtractionContext.previousUserText` 声明了、prompt 渲染了 `<previous-user>`，**但从没有任何地方赋值**。它和候选近轮一起，构成"这一轮接着什么"的最小上下文。

### 4. 解析失败的通路改变

| 模型输出 | 0017 | 本 ADR |
|---|---|---|
| `继续 t_ab12` 且 id 存在 | 挂该线索 | 同 |
| `继续 t_xxxx` 但 id 不存在 | 开新 | **接到上一轮所属线索**（若同会话）；否则开新 |
| `无` / 解析失败 | 开新 | **接到上一轮所属线索**；全无则开新 |

## 后果

**接受的代价**

- 可能出现"两个话题合成一条线索"。代价是一条偏的结论，可被 supersede，且线索可事后拆分。
- 线索主题（一句话）在混用时不够准确。缓解：闭合时用归纳出的主题替换（0017 §4.2 已有）。

**必须同时做的事**

- **事后修复入口**：线索可合并/拆分（后置，先不做界面，只留数据能力）。
- **归属可审计**：每轮记 `thread_join_reason`（continue / explicit-new / fallback-previous / no-context），否则无法判断改动的效果。
- **先修归属再补历史**：210 条待抽取轮次若按旧归属重跑，会再生成 200 条单轮线索，把数据变得更碎。

## 验收（可证伪）

改动上线后，同一批对话（补齐 210 条后）应满足：

| 指标 | 现在 | 通过线 |
|---|---|---|
| 每轮归属率 | 42% | ≥ 90% |
| ≥2 轮的线索占比 | 9 / 123 = 7% | > 50% |
| 有 ≥2 条事实的线索 | 4 / 123 | > 30% |
| 关闭 10 条线索产出的结论 | 0.2 条 | ≥ 5 条 |
| 结论证据可追到线索内轮次 | 未测 | 100% |

**达不到就说明判据还是错的**，回到本 ADR 重定，不进入下一步。

**修订（2026-11-06，0028 ⑤）：口径改段级——上表原文保留作历史口径。** 归属已是段抽取的产物（0028 ③：段内多线索 spans、每轮挂线），于是：

- **每轮归属率**：分母 = 窗口内轮次 **− 仍在缓冲的轮次**（`pending-extract`——它们在等离开点，决定 4 认的 1 轮延迟不是"没归属"）；分子 = 其中 `turns.thread_id` 非空的。上表的 42% 用的是全量分母。
- **归属原因分布**：`join=` 在 ③ 后是一段的逐轮原因**并集（去重）**——按段读（一段出现过的原因各计一次），不再当逐轮计数；单原因行与旧算法逐字一致。
- 其余四行（≥2 轮线索 / ≥2 事实线索 / 每 10 关闭结论 / 证据可追溯）本就线索级，口径不变。
- 实现：`scripts/attribution-stats.mjs`（同批改；通过线那行显示一位小数，整数四舍五入会把 89.9% 显示成 "90% FAIL"）。

## 不做什么

- 不做多归属（一轮属于多条线索）。
- 不做完美切分——本 ADR 的目标不是"切得准"，是"能形成章节"。
- 不引入新表：`threads` + `turns.thread_id` 够用；新增的是 prompt 输入与解析通路。

本 ADR 修订：§3 的取舍（改成碎片化更贵）、§4.2 的默认值（不确定时不新开）与候选内容（加近轮原文）。

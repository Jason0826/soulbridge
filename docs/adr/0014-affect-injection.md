# ADR 0014：注入策略与反谄媚

- 状态：Accepted
- 日期：2026-10-28
- 关联：ADR 0017（正确性护栏）

## 背景

把"用户情绪"注入到别人的系统提示里，有两个失败模式：

1. **断言内心**："用户很焦虑"——模型可能据此表演共情，而判断本身可能是错的。
2. **谄媚**：模型为了"照顾情绪"而在事实判断上让步。

两者都比"不注入"更糟。

## 备选

1. 自由生成一段情绪描述：表达力强，不可审计。
2. **固定白名单 + 置信度门槛**：表达力受限，但每一句都可追溯。
3. 不注入，只落库：最安全，但 v0 没有产品价值。

## 决定

选 2。

**白名单（5 条，`directives.ts` 为唯一来源）**

| id | 触发 | 文本 |
|---|---|---|
| `negative_high` | valence ≤ −0.4 且 intensity ≥ 6 | 对方情绪偏负面：先承接，再给方案；不要急着讲道理 |
| `positive_high` | valence ≥ 0.4 且 intensity ≥ 6 | 对方情绪偏正面：回答可以更简短 |
| `hedging` | 犹豫词 ≥2 且 ≥6/百 token | 对方表达里犹豫词偏多：给结论，少加限定语 |
| `fragmented` | 填充词 ≥3 且 ≥8/百 token | 对方表达较碎片：先复述你的理解，再回答 |
| `vague_terms` | 笼统词 ≥3 | 对方用词较笼统：必要时确认具体所指 |

**门槛**：`confidence < 0.6` 或 `hits = 0` → 整段不注入；最多 2 条；预算 160 字符，放不下整段丢弃。

**格式**：`<affect confidence="0.67" analyzer="lexicon">`，`analyzer` 字段让注入可追溯到规则还是模型。

## 后果

**正面**

- 注入内容可枚举、可测试（T6 断言只可能来自白名单）
- 永不出现"用户很焦虑"这类断言——只描述**表达特征**

**负面**

- 表达力受限，看起来"不够聪明"
- 阈值需要调；调的依据是黄金集与 P3 实验，不是手感

**反谄媚的实现方式**

注入只改变措辞指令，`selectDirectives` 的输出里**不含任何关于事实判断的措辞**；正确性护栏由 ADR 0017 的第四条判据强制。

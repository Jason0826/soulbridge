# ADR 0009：v0 不做内容记忆适配器

- 状态：**Accepted**（2026-10-27 确认）
- 相关：ADR 0003（存储分层）

## 背景

"内容记忆"（对话原文、文档、代码库知识）是记忆产品的主战场，也是 Supermemory / Mem0 已经占住的位置。

而本项目的假设是：人格型的"选择记忆"不随上下文变大而贬值，容量型的"检索记忆"会。若 v0 就接一个内容检索服务，等于把验证重点悄悄换成了它擅长的部分。

## 备选

1. **v0 只做人格状态 + 关键词兜底**，内容记忆留端口。
2. v0 接一个外部服务（Supermemory / Mem0）作为内容记忆。
3. v0 自研向量检索。

## 决定

选 1。

- v0 的记忆只有人格状态（7 类），检索靠关键词 + 打分（已有实现）；
- `SoulStore` 预留内容检索的位置，但不实现 adapter；
- 若 v0.1 评估显示"记不住原文"是主要缺口，再在 v0.2 接外部服务。

## 后果

**正面**

- 假设检验不被外部服务的能力掩盖：好坏都归因于我们自己的选择逻辑；
- 依赖为零，安装仍是 `npx`；
- 评估口径干净（ON/OFF 只差我们自己的实现）。

**负面**

- "帮我找上次那段代码"这类请求在 v0 做不好；
- 用户可能觉得"记忆不够强"，把差异化误读为缺失。

**触发重新评估的条件**

- v0.1 单臂评估中，`no_repeat` 无明显改善且用户反馈集中在"记不住细节"；
- 或集成 T1 后发现 transcript 本身已能提供足够上下文，无需独立内容库。

# ADR 0019：与 steering 文件（AGENTS.md / CLAUDE.md）的边界

- 状态：Accepted
- 日期：2026-10-28

## 背景

"让 agent 记住东西"这件事，已经有人做得很好：仓库级 `AGENTS.md`、用户级 `~/.claude/CLAUDE.md`、Cursor 的 User Rules。它们持久、可评审、可版本化、零基础设施。

问题：既然如此，soulbridge 还有存在的必要吗？

## 能力对比

| 能力 | 仓库级 AGENTS.md | 用户级 steering | soulbridge |
|---|---|---|---|
| 项目约定、团队共享 | ✅ 强 | ❌ | ⚠️ 不做 |
| 可评审、可版本化 | ✅ 强 | ⚠️ 弱 | ⚠️ 不做 |
| 单人偏好持久化 | ✅ | ✅ | ✅ |
| **跨工具**（Claude Code ↔ Cursor ↔ Pi） | ❌ | ❌ 各家各管一份 | ✅ **唯一位置** |
| **自动维护**（抽取/遗忘/取代） | ❌ 靠人记得改 | ❌ | ✅ |
| **选择与时机**（注入 3 条而非 2000 行） | ❌ 全文常驻 | ❌ | ✅ |
| **可度量** | ❌ | ❌ | ✅ |
| 隐私（个人记忆不进仓库） | ❌ | ✅ | ✅ |

## 决定

1. **不替代**：不生成、不接管 AGENTS.md
2. **可导入**（R3）：`soulbridge import --from claude-md|agents-md`，把已有 steering 文件读成 `fact`/`strategy` 记忆，一次性、去重
3. **只做三件事**：跨工具携带、自动维护、注入选择（外加可度量）

## 必要性判据（README 要写）

| 用户画像 | 建议 |
|---|---|
| 单工具 + 单仓库 + 愿意手动维护 | **别用我们**，AGENTS.md 够了 |
| 多工具 / 多仓库 + 有个人偏好 | 我们是唯一解 |
| 团队共享约定 | 用 AGENTS.md，我们不抢 |

## 可证伪的三条（P3）

| 实验 | 设计 | 失败意味着 |
|---|---|---|
| E4 跨工具携带 | 工具 A 纠正一次，次日工具 B 的 context 是否包含该策略 | 定位失守，项目失去意义 |
| E5 注入选择 | 200 字注入 vs 整份 steering 文件，遵循率对比 | "全塞进去"也行，我们多余 |
| E6 自动 vs 手工 | 4 周内自动抽取 vs 人工维护的 steering 文件 | 人更可靠，降级为辅助工具 |

## 后果

**正面**

- 定位从"我也有记忆"变成"补三件结构上做不到的事"
- README 主动劝退不适用的用户，减少失望

**负面**

- 可服务的用户群明显变窄（多工具用户）
- 一旦宿主提供跨工具用户级记忆，本项目失去位置（写进放弃条件）

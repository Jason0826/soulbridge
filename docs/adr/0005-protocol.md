# ADR 0005：四动词协议 + 语义化版本

- 状态：Accepted
- 日期：2026-10-27
- 相关：`docs/spec/protocol.v0.md`

## 背景

宿主之间的生命周期接口差异极大（hooks、扩展、MCP、纯指令）。若按宿主定义 API，每接一个新宿主都要改 core。

需要一个**最小的、与宿主无关**的动作集合，让 adapter 只做翻译。

## 备选

1. 按宿主给 API（`forClaudeCode()` / `forPi()`）：清晰但核心会分叉。
2. 暴露完整能力（记忆 CRUD、图谱、策略查询）：灵活，但契约不可穷尽，贡献者无法判断"什么算兼容"。
3. **四个动词 + 版本号**：`context` / `observe` / `recall` / `reflect`。

## 决定

选 3。

| 动词 | 时机 | 契约要点 |
|---|---|---|
| `context` | 会话开始 | 受 `maxChars` 硬约束；只丢弃不截断；返回 `used` |
| `observe` | 每轮结束 | 同步、无模型、<5ms；永不抛给宿主 |
| `recall` | 需要时 | 调一次即 `recallCount++` |
| `reflect` | 会话结束 | 可降级为规则抽取；不阻塞退出 |

版本策略：

- 协议自带 `protocolVersion`（`MAJOR.MINOR`）；
- **只允许加字段**在 MINOR；删字段/改语义必须升 MAJOR；
- 未知字段一律忽略，不得报错；
- 每个动词必须定义"失败时的返回"，不允许"失败即无返回"。

## 后果

**正面**

- adapter 只是翻译层，core 不随宿主变化；
- 契约小到能整页读懂，测试可以穷举；
- 版本号让"破坏性变更"变成一次显式决定，而不是悄悄发生。

**负面**

- 表达力受限：宿主的特殊能力无法直接暴露（例如"当前打开的文件"），只能挤进 `context` 的请求字段；
- 跨宿主的语义漂移需要靠 spec 的示例约束。

**待验证**

- 第二个 adapter 接入时，core 改动是否 <20%（若不达标，说明协议抽象错了）。

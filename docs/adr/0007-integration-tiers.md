# ADR 0007：接入分四级阶梯，验证宿主是 DSH

- 状态：Accepted
- 日期：2026-10-27
- 相关：ADR 0005、RFC 0001

## 背景

"接一个宿主"不是单一动作。不同宿主提供的能力差别极大，而本机环境又限制了我们能验证什么（**没有安装 Claude Code**）。

已核实的环境事实：

- 本机有 DSH（DeepSeek Harness），会话语义为事件流，落盘在
  `.dsh/sessions/<workspace>/<session-id>/session.v4.jsonl.zstd`；
- Node 24 自带 zstd 解压，**transcript 可读**；
- `.dsh` 目录下未发现 MCP 配置，因此不假设 MCP 可用。

## 备选

1. 只做 hooks（依赖宿主生命周期 API）：体验最好，但当前无法验证。
2. 只做 MCP：覆盖面广，但拿不到完整对话，反思会退化成"模型主动存笔记"。
3. **分级阶梯**：从零依赖到深度集成，逐级验证。
4. 针对单个宿主写死：不可移植。

## 决定

选 3，定义四级：

| 级别 | 形态 | 依赖宿主 | 可验证性 | 目标版本 |
|---|---|---|---|---|
| **T0** | `SKILL.md` + CLI | 能读指令、能跑命令 | ✅ 立即可验证 | v0.1 |
| **T1** | transcript 摄取 | 会话文件可读（DSH 的 zstd jsonl） | ✅ 已有样本 | v0.1 |
| **T2** | hooks / 扩展 | 宿主生命周期钩子（Claude Code） | ❌ 无环境 | v0.2 |
| **T3** | MCP server | 宿主支持 MCP | ❌ 本机无 | v0.3 |

**验证宿主 = DSH；发布宿主 = Claude Code。**

判断依据：T0+T1 已经足以验证核心假设（跨会话连续性、重复提问是否下降），T2/T3 是体验优化，不是正确性前提。

## 后果

**正面**

- 今天就能端到端跑通，不依赖未安装的软件；
- 接入成本对用户是"复制一个 md 文件"，不是"装插件"；
- T2/T3 延后，避免为无法验证的接口设计抽象。

**负面**

- T0 依赖模型自觉执行指令（又回到"希望层"）——必须用 T1 的自动摄取补偿；
- T1 依赖宿主的私有存储格式，DSH 一改就断，需要隔离在 adapter 内。

**待验证**

- T1 读取 DSH 会话格式的稳定性（格式版本号、字段变更）。
- 若 T0 的真实遵从率低于预期，T2 优先级需要提前。

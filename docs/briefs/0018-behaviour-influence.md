## 问题

我们已经能存：事实、结论、情绪、线索。**但没有一条路保证这些会改变回复。**

现在的注入是**资料**，不是**指令**：

```
<memories>锚点</memories>
<about>人物时间轴</about>
<affect>对方情绪偏负面</affect>
```

三件事同时缺失：

| 缺什么 | 后果 |
|---|---|
| 触发条件 | 不知道什么时候该用 |
| 动作要求 | 知道"负面"，但没人说"所以先承接" |
| 后果 | 忽略了也没有任何反馈 |

## 三层模型（提案）

```
L1 确定性约束   能用代码拦的，绝不靠模型
                例："改 JSON 别用字符串替换" → 工具层检查
L2 指令注入     不能代码拦的，变成"触发条件 + 动作"
                例：情绪负面 → "第一条先说理解，本轮不推进任务"
L3 反馈闭环     做没做到要有观测；没做到要能升级
                例：同一教训被纠正两次 → 升级为每轮常驻
```

## 最小切片：教训 → 行为（先做这个，不是情绪）

理由：**教训有客观失败信号（用户纠正）**，情绪没有。

```
1. 存储：教训 = fact，三类槽位
     触发 = 工具/pwsh 改 JSON
     做法 = 用 edit 工具或 BOM 安全写入
     证据 = 哪一轮被纠正

2. 触发：pre-step 用规则匹配（工具名 / 文件类型 / 关键词）
   —— 确定性，不靠模型判断"适用不适用"

3. 注入：<rules trigger="…"> 放在注入块末尾（离回复最近，且是指令不是资料）

4. 观测：注入次数 / 随后 3 轮内被纠正次数 = 遵守率

5. 升级：同一教训被纠正 2 次 → 进 section（常驻）
```

**第 4 条是关键**：没有遵守率，L2 就又是一个 hope。

## 情绪怎么接进来

不做"注入一段描述"，做"一条带触发条件的指令"：

```
触发：情绪=负面 且 强度≥6
做法：第一条先说理解；本轮不主动推进任务
```

可观测性弱于教训（判断仍是软的），但至少有样本。

## 顺序

| 顺序 | 内容 | 为什么 |
|---|---|---|
| 1 | 教训 → 行为 | 有客观信号 |
| 2 | 情绪 → 行为 | 复用同一触发机制 |
| 3 | 结论 → 行为（画像影响语气） | 最软，最后 |

## 为什么现在不做

1. 线索层（0017）还没跑通验收，主线不能并线
2. 行为影响的验证方法（遵守率）依赖纠正样本，需要先积累
3. 先把"记得对"做扎实，再谈"用得上"——顺序反过来会两头空

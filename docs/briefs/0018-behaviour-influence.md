## 一、问题（2026-11-02 原文，诊断仍成立）

我们已经能存：事实、结论、情绪、线索。**但没有一条路保证这些会改变回复。**

现在的注入是**资料**，不是**指令**：

```
<memories>锚点</memories>
<about>人物时间轴</about>
<affect>对方情绪偏负面</affect>
```

三件事同时缺失：

| 缺什么 | 后果 |
|---|---|
| 触发条件 | 不知道什么时候该用 |
| 动作要求 | 知道"负面"，但没人说"所以先承接" |
| 后果 | 忽略了也没有任何反馈 |

## 二、文献（2026-11-06 检索，四篇钉死四件事）

| 文献 | 钉死什么 |
|---|---|
| [Control Illusion: The Failure of Instruction Hierarchies](https://arxiv.org/abs/2502.15851)（AAAI-26） | **prompt 层不可靠是实证结论**：六个前沿模型，system/user 分层指令建立不起可靠优先级，模型对约束类型有固有偏好——"模型可以不做"不是错觉。**所以解法不许停在 prompt** |
| [When Should the Agent Speak?（TMLR 综述）](https://tmlr.infinite-conf.org/paper_pages/b0yKEdAXEr.html) | **决策只有一条规则：intervene iff 预期行动收益 > 预期打断成本**；五层组织 signals / decision / action / memory / evaluation；**evaluation 是 gating layer**——没有可验证的 outcome，主动性全是 hope |
| [Proactive Service Agents: A Unified Decision Framework](https://arxiv.org/abs/2609.03727)（2026-09） | **动作四选一：silent / asking / assisting / acting**，各计打断、误解、越权、隐私四类成本；"**long-term memory is not a defining condition of proactivity**"——光有习惯记忆不构成主动性，必须有 decision gate |
| [ProAct: Idle-Time Compute in Proactive Agents](https://arxiv.org/abs/2605.25971) | **主动性挂交互间隙（idle-time），不挂对话中间**：预测下一步需求并提前准备，实测少 14.8% 轮次、省 11.7% 用户 effort、幻觉降 28.1%——与 0028 离开点同构（事件/空闲时做事，不打断对话） |

工程先例（触发器机制不是我们发明的）：[HookBus: lifecycle event router for AI agents](https://zenodo.org/records/19679628)、[nanoclaw 的 compact 80% 提前预警](https://github.com/nanocoai/nanoclaw/pull/1890)。

## 三、三层模型 → 五层落地（原提案升级：映射，不推翻）

原三层（2026-11-02，仍有效）：

```
L1 确定性约束   能用代码拦的，绝不靠模型
L2 指令注入     不能代码拦的，变成"触发条件 + 动作"
L3 反馈闭环     做没做到要有观测；没做到要能升级
```

映射到综述五层（升级点加粗）：

```
L1 → action 的 acting 档：能代码拦的绝不靠模型
      已有实例：health-check 差异体检（机械编辑损坏）、退场/声明检查
L2 → signals + decision + action
      signals   触发器注册表：声明式一行 {signal, 条件, 动作模板, 冷却}
                —— 新习惯 = 加一行，不改代码路径（§0 验收线的载体）
      decision  cost-gate：不只看阈值，还要看打断成本
                v1 = 阈值穿越 + 每级只说一次（防墙纸即打断成本的粗代理）；
                v2 = 低打扰窗口细化（turn 完成、输入短的回合优先）
      action    四选一，默认 silent；compact 建议 = asking
L3 → evaluation（gating layer）
      遵守率：注入后模型说了没有（复用 rule-compliance 的思路）
      outcome：说了之后采纳没有——建议后 N 轮内 compaction/end 或
               switch_session 出现 = 采纳（事件流现成，可直接算）
```

## 四、习惯三分类（不是所有习惯都是主动性的题）

| 分类 | 机制 | 承诺 | 未来习惯实例（映射推演） |
|---|---|---|---|
| **状态类**（signal 可测） | 触发器注册表（L2） | 触发即注入 | 上下文到线→建议 compact；缺口 14 天没答→找时机问；刚发版→提醒 npm 复制延迟 3–15 分钟；情绪负面≥6→先承接（0018 原例） |
| **语义类**（聊到/用到 X） | 规则层（已有 selectRules + fired） | 匹配即注入，**精度有限**（structural:negation 实测 25/28 误判在案） | 改 JSON 想到用 edit——**能 L1 的优先升 L1**（体检已接过一条），轮不到 L2 猜 |
| **知识 / 风格类** | 记忆、section 注入 | **只当背景，不承诺行动** | "npm 延迟"这类知识；"回答看整体"这类风格 |

## 六、边界（不做什么）

1. 不承诺语义主动性的精度——误判数据在案；能代码拦的进 L1（体检），不靠 L2 猜。
2. 不做"模型自发"——`soul_recall` 主动调用 0 次，任何 prompt 改变不了（Control Illusion 同向）。
3. 不动三层注入（ADR 0033）与 handoff 门牌自动——后者已经是本设计的实例（触发=新会话开场，动作=自动注入）。
4. 记忆不承诺行动（§四第三行）；要行动就升格成触发器行或规则。

## 七、原最小切片（教训 → 行为）降为第二刀

理由：它依赖语义匹配（触发 = 工具名/文件类型/关键词），精度弱于状态类；第一刀选信号已在手上的状态类。

```
1 存储：教训 = fact，三类槽位（触发 / 做法 / 证据）
2 触发：pre-step 规则匹配；能代码拦的直接升 L1（体检模式，已成功一条）
3 注入：<rules trigger="…"> 放注入块末尾（指令不是资料）
4 观测：注入次数 / 随后 3 轮内被纠正次数 = 遵守率
5 升级：同一教训被纠正 2 次 → 进 section（常驻）
```

**第 4 条是关键**：没有遵守率，L2 又是一个 hope（综述：evaluation is the gating layer）。

# 需求说明：会话层（Conversation）

- 状态：Draft
- 日期：2026-11-01
- 关联：[mvp.md](../mvp.md) MVP1、[0010 记忆单元](0010-memory-unit.md)、RFC 0007

---

## 1. 需求（消费者与决定）

| 消费者 | 什么时候 | 要做什么决定 | 需要什么信息 |
|---|---|---|---|
| 模型 | 新会话第一句"上次聊到哪" | 说出上次的主题、决定、稳定事实 | 哪次是"上次" + 那次的首尾 |
| 注入构建器 | 每轮 | 注入片段还是会话交接 | 当前会话是否刚开始 |
| 用户 | 事后 | 它用的是记忆还是残留上下文 | 来源会话 id |

**实测问题**（2026-11-01）：`recallTurnPairs("我们上次聊到哪了")` 返回 5 条，
但内容不是"上次的主题"——是最近几轮。原因：问句没有区分度（"我们/上次/聊"到处都有），
BM25 打分接近，退化成按时间排。

## 2. 文献

| 来源 | 结论 | 对我们的含义 |
|---|---|---|
| **事件分割理论**（Zacks & Smith 2025，[APS 综述](https://www.psychologicalscience.org/publications/observer/teaching-current-directions-life-chunks.html)） | 人按事件边界切分连续经历；**边界处的内容记得更牢**；分割本身就是 chunking，块间不易干扰 | "会话"就是天然的边界。平铺片段缺这个结构，所以"上次"无从谈起 |
| **生成式 agent 检索**（Park 2023） | 新近度 × 重要度 × 相关性 | 会话交接靠**时间**，不是相关性 |
| **Ebbinghaus / 间距效应** | 衰减从上次被召回算起 | 会话内片段的时效应基于会话时间 |

**边界**：文献讲的是人类记忆，不是 LLM 记忆。我们只用它的**结构结论**（分段有用），不搬具体参数。

## 3. 划边界

| 做 | 不做 |
|---|---|
| 会话边界识别（按 `session_id` 派生） | LLM 生成的会话摘要 |
| 交接单：时间段 + 首条 + 末 2 条 | 主题模型 / 关键词抽取 |
| 新会话前 2 轮注入交接单 | 每轮都注入 |
| 不新增表（从 `turn_pairs` 派生） | 新增 `sessions` 表 |

## 4. 声明（可验证）

1. 会话可由 `turn_pairs.session_id` 分组确定，边界 = 分组边界。
2. 新会话首次请求时，能确定"上一个会话"是**最近一条不属于当前会话的 pair** 所在会话。
3. 交接单（首条 + 末 2 条）足以让模型说出上次的主题与决定——**这条要靠验收证伪**。
4. 注入交接单不会让当前会话的片段检索失效（两条路径互不覆盖）。

## 5. 验收

```
# 1. 派生正确（不改库即可验证）
node scripts/session-index.mjs
  → 应列出会话 id、起止时间、条数；最近的排前面

# 2. 交接单内容正确
  → 与 turn_pairs 里该会话的首条、末两条逐字一致

# 3. 真实场景（最终判据）
关掉 DSH → 重开新会话 → 问"我们上次聊到哪了"
  → 3 次里 ≥2 次说出主题与决定；0 次编造
```

## 6. 不通过怎么办

若交接单注入后仍答不对，说明**问题不在边界而在摘要**（首尾不足以概括），
那时才考虑 LLM 摘要——**先证伪，再上成本更高的方案**。

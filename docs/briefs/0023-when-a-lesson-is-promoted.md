# 0023 · 什么时候把一条经历升格为教训／规则（文献 + 判据）

> 状态：**判据已定，未实施**。这是 ①「谁把新教训放进分类队列」的前置研究。
> 顺序：需求 → 文献 → 边界 → 声明 → 验收。
>
> **2026-11-07 修订注（候选门已改口径，本节以下原文保留）**：0018 §九 3 第二刀 A 落地时用户拍板
> **候选门 = 全部教训入队分桶**（b），不再「先只开 T1、观察三天」。T1 从**门**降为**桶**：
> 队列原因 `T1-修正`（批序第一）与 `全收`（没有任何纠正信号）；存量另有一桶 `存量`。
> 理由就是本页 §二 的反面：升格门槛低会产废，但 T1 作为**唯一**入口时，「SQLite `date()` 把数字
> 当儒略日」这类从不被用户纠正的教训永远进不来。T2（复现）/ T3（积压）仍未开，K 仍未拍。

## 一、需求

现在三段管线里最上游是空的：

```
经历 →[① 谁放进来？]→ 分类（规则/画像/待修）→[② 已接]→ 画像队列 →[③ 已接]→ 按维度合并
```

今天之前的做法是**手工脚本**按 `type_name IN ('教训','原则','性格')` 塞队列。这是
"人记得跑脚本"才成立的设计，而且**按标签选，不按重要性选**——模型可以把同一件事写成
16 种标签（实测：26 条事实 16 种标签），标签本身不可靠。

所以问题不是"加个定时器"，而是：**凭什么判断一条经历值得升格**。

## 二、我们现在的实测（2026-11-02，`scripts/rule-stats.mjs`）

```
活跃事实：规则 61 · 事实 30 · 画像 9 · 待修 7 · 其他 14
61 条规则全部有触发条件
trace 里触发过的不同规则：10/61（16%）
从未触发的：51 条
画像行没有来源的：1 条
```

**解释要克制**：16% 不全是"产废"，有些规则本来就低频（例如"schtasks /Run 在上一实例未结束时被静默忽略"）。
但这个数字说明**升格门槛太低**：128 条旧教训里升格了 61 条规则（48%），
而每条规则当初都只出现过一次。

## 三、文献怎么说

| 文献 | 关键结论 | 对我们意味着什么 |
|---|---|---|
| [Generative Agents / memory stream](https://raw.githubusercontent.com/agentpatterns-ai/website/refs/heads/main/patterns/agent-design/generative-agents-memory-stream.md)（Park et al. 2023） | 每条观察由模型打一个 **poignancy**（重要度）；**反思不是按时间表，而是累积重要度越过阈值时触发**；反思从 3 个焦点出发，产出 5 条上层洞见，**带证据链**，写回记忆流 | 升格要由"积累"驱动，而不是"来一条处理一条"；升格的第 1 步是挑焦点，不是逐条分类 |
| [ExpeL](https://arxiv.org/abs/2308.10144)（Zhao et al., AAAI-24） | 智能体自己收集经历、抽取**自然语言洞见**，推理时召回；**随着经历积累性能持续提升** | "教训"可以是一条自然语言句子，不需要 schema 化；但要有池子与增删 |
| [Contextual Agentic Memory is a Memo, Not True Memory](https://arxiv.org/abs/2604.27707)（Xu et al. 2026） | 检索只是查找，**不是记忆**；只做查找的系统会"无限积累笔记却长不出专长"；用互补学习系统（CLS）解释：海马快速存个案 + 皮层慢速巩固成规则 | 我们已经有 facts（个案）与 规则/画像（巩固层），**缺的是巩固的触发条件**；这正是 ① 要补的 |
| Tulving（1972）情景／语义二分（转引自 [position paper](https://zenodo.org/records/20078453/files/zenodo_LLM_wiki_position_paper.pdf?download=1)） | 情景记忆（某时某地发生）与语义记忆（脱离情境的知识）是两类 | 一条经历留在情景层是默认；升格成语义层（规则/画像）是**例外**，需要理由 |

**共同点**：三份都在说"不是每条经历都该沉淀"，差别只在**凭什么**：

- Generative Agents：累积的重要度
- ExpeL：与已有洞见的对比（新洞见才加）
- CLS：重复再现（reinstatement）

## 四、边界（不借什么）

| 不借 | 为什么 |
|---|---|
| 存 `poignancy` 分数长期用于排序 | 我们的 ADR 0027 明确：要理解含义才算得出的值不进 schema。分数只用于**触发**，不用于检索排序 |
| 固定阈值 150（他们的口径） | 他们的观察粒度是"事件"，我们是"事实"，不可直接换算。阈值必须用我们自己的数据标定 |
| 反思一次产出 5 条 | 条数是他们的产品参数，我们已经有画像合并的分层，不重复第 5 条 |
| 强制 schema 化教训 | ExpeL 证明自然语言洞见够用；我们只是需要"分类"这一步来决定进哪一层 |

## 五、判据（三条触发，代码判定，模型分类）

一条新事实进入分类队列，当且仅当满足其一：

| 触发 | 判定 | 依据 | 代码可否判定 |
|---|---|---|---|
| **T1 修正** | 该事实所在轮次被标为纠正（用户说"不对/不是这样/错了"） | 后果强度高（ExpeL：失败经验产出更多洞见） | ✅ `corrections` 表已有 87 条 |
| **T2 复现** | 与某条**已存在事实**的 gist 相似度 ≥0.7（同一原则换说法） | 重现即巩固（CLS / reinstatement） | ✅ 已有 bigram 相似度 |
| **T3 积压** | 未触发 T1/T2 的"原则候选"累计到 K 条未分类 | 累积重要度阈值（Generative Agents） | ✅ 计数器 |

**只进不出的保持原样**：单次出现、无重现、无修正的事实 → **留在记忆层**（facts），
不进规则/画像。它仍然可被检索、仍然在库里；只是不升格。

**"原则候选"怎么判**：交给模型在抽取时给一个二值标记（是/否"关于怎么做事的经验"），
而不是 `type_name` 白名单。理由是实测标签漂移（16 种标签）。这个标记是**分类器的输入**，
不是排序权重，符合 0027。

## 六、验收（都能从库里算，不靠感觉）

| 指标 | 定义 | 通过线 | 现状 |
|---|---|---|---|
| 升格率 | 每 100 条新事实升格出的规则/画像条数 | ≤20 | 未知（旧数据 48%） |
| 单次升格占比 | 只由 1 条事实支撑的规则占比 | ≤30% | ~100% |
| 触发覆盖率 | 已升格规则中至少触发过一次的比例 | ≥40%（观察窗口内） | 16% |
| 队列可解释 | 每条入队记录带 T1/T2/T3 理由 | 100% | — |

**回滚**：T1–T3 任一判定都是代码算的，关掉开关即退回"手工脚本"，数据不动。

## 七、实施顺序（最小）

1. 抽取 prompt 加一个二值标记 `原则候选: 是/否`（一个词，不新增分数）。
2. 抽取落库后，代码按 T1/T2/T3 判定是否入队；入队项带 `reason`。
3. 分类队列每项带 `reason`，日志按 reason 计数（这就是"队列可解释"指标）。
4. 先只开 T1（最确定），观察 3 天；再加 T2；T3 最后。

## 八、开放问题

| 问题 | 现状 |
|---|---|
| K（积压阈值）取多少 | 需要 T1/T2 的实测流量再定，先不拍 |
| 相似度用 bigram 够不够 | 够判断"同一句换说法"，不够判断"同一原则的两个例子"——后者要靠模型，暂不做 |
| 规则触发率低是"没用"还是"低频" | 无法区分（没有"该触发而没触发"的标签）。这是评测缺口，记在这里 |

# 需求说明：主题线索（threads）

- 状态：Draft
- 日期：2026-11-01
- 关联：[0016 提取与归纳](./0016-extraction-consolidation.md)、[dsh-runtime](../dsh-runtime.md)
- 由来：用户指出的单位错误——**一问一答不是一章**，用它做归纳等于"读了两三章就说懂整本书"

---

## 1. 需求

归纳（0016）的输入单位现在是「一批新事实」。这有两个毛病：

| 毛病 | 后果 |
|---|---|
| 按**数量**触发（凑够 5 条） | 一段话还没说完就开始总结 |
| 事实**跨主题混在一起** | 把 cookie 的事和记忆的事混成一条结论 |

消费者要的是：

| 问题 | 需要的单位 |
|---|---|
| 上次我们定的方案是什么 | **一段讨论**（可能 3–20 轮） |
| 他最近怎么样 | 关于某个人的**多条**事实，跨主题 |
| 不用重复交代 | 跨所有主题的**稳定结论** |

第一行要的是「线索」，第二行要的是「实体」，第三行要的是「长期结论」。

**本轮只补第一行：线索。**

## 2. 文献

| 来源 | 结论 | 对我们的含义 |
|---|---|---|
| [TextTiling](https://aclanthology.org/W08-18.pdf)（Hearst 1997） | 把**线性文本**切成子话题段落 | 假设不成立：对话会回头 |
| [Conversation Disentanglement](https://aclanthology.org/P19-1374/)（Kummerfeld et al., ACL 2019） | 把**交织**在一起的多条对话拆成独立线索 | 正是我们的场景；单位是线索，不是段落 |

**结论：不做"切分"，做"归属"。** 一条线索的轮次可以不相邻。

## 3. 边界

| 做 | 不做 |
|---|---|
| 一轮归一条线索 | 一轮归多条（暂不做多归属） |
| 线索可跨轮次、可跨会话 | 完美的边界检测 |
| 不确定就开新线索 | 高置信合并（合并交给事后） |
| 线索闭合时归纳一次 | 每轮边聊边归纳 |

**核心取舍**：错判的代价不对称。

```
错开新线索 → 话题碎，但结论仍然正确
错接到旧线索 → 两件事混成一条结论（污染）
```

所以默认保守：**不确定就开新的**。

## 4. 设计

### 4.1 数据（schema v7）

```sql
threads(
  id, soul_id, user_id, session_id,
  topic,              -- 一句话主题，由模型给
  status,             -- open | closed
  opened_at, closed_at,
  last_turn_no,
  summary_fact_id     -- 闭合后归纳出的结论（可为空）
)
turns.thread_id       -- nullable；只能指向同 soul 的线程
```

不建索引表、不做多对多。一轮只有一个归属。

### 4.2 归属：复用抽取那一次调用

抽取 prompt 的表格里加一行（和 `实体/事实/缺口` 同级）：

```
线索: 继续 t_ab12
线索: 新 | 在聊 cookie 与认证
```

**候选清单长什么样**（模型实际看到的）：

```
<open-threads>
  t_ab12 | 记忆分三层怎么落地 | 2 轮前
  t_cd34 | cookie 为什么失效 | 1 轮前
</open-threads>
```

每条候选三样：**id**（模型只能回 id）、**主题**（≤20 字）、**多久前提过**（轮数）。

| 规则 | 值 | 为什么 |
|---|---|---|
| 最多给几条 | **5**（临时值，等真实数据调） | 给多了模型开始抓关键词硬匹配 |
| 顺序 | 最近提到在前 | 多数情况答案是"跟上一轮一样" |
| 主题长度 | ≤20 字 | 太长会退化成关键词匹配 |
| 无候选时 | 不渲染该块 | 模型只能开新 |
| 上一轮已知 | 追加 `上一轮所属：t_cd34` | 把最可能的答案摆在它面前 |

**解析规则**（所有失败路径都通向"开新"）：

| 模型输出 | 处理 |
|---|---|
| `继续 t_ab12` 且 id 存在 | 挂到该线索 |
| `继续 t_xxxx` 但 id 不存在 | 开新（防幻觉） |
| `新 \| 主题` | 建线索 |
| `无` / 解析失败 | 开新，主题取该轮前 20 字 |

主题的来源与更新：开新时由模型给一句；线索**闭合**时用归纳出的主题替换（更准）。

**零额外调用**：归属搭在已有的抽取上，净增约 80–150 字符。

### 4.3 闭合

一条线索在下列任一条件闭合：

| 条件 | 阈值/来源 |
|---|---|
| 空闲 K 轮 | 默认 K=6（可配） |
| 会话结束 | 下一个会话开始时 |
| 用户显式结束 | "这事定了 / 不聊这个了" |

闭合时记录 `closed_at`，并触发一次归纳（0016 的两阶段：起草 + 独立验证）。

### 4.4 归纳按线索跑

```
输入：该线索的全部轮次（正文）+ 由这些轮次抽出的事实 + 已有相关结论
输出：一条结论（带证据：事实 id 与轮次 id）
      + 该线索的一句话主题（用于之后"上次聊到哪"）
```

替换掉现在的「事实凑够 5 条就归纳」。

### 4.5 注入

"上次聊到哪"改为按**最后一条闭合线索**取：

```
上一线索的主题 + 它的结论 + 最后 1–2 轮
```

## 5. 声明（可证伪）

1. 在一段 A→B→A 的交织对话里，线索 A 的轮次集合包含两段 A 而不包含 B。
2. 线索 A 闭合后归纳出的结论，**必须引用第二段 A 的证据**；若只引用第一段 A，则等价于"只读了两三章"。
3. 未闭合的线索**不产生结论**。
4. 归属判错时，只会产生多条碎线索，不会把两条不同主题合并（保守性）。

## 6. 验收

固定场景（手工构造，可重复）：

```
A1 记忆分三层
B1 cookie 为什么失效
A2 回到三层怎么落地
B2 cookie 的结果
A3 定：归纳按线索跑
（再等 6 轮无关对话）
```

| 检查 | 通过线 |
|---|---|
| A 线索包含 | A1、A2、A3（不相邻） |
| B 线索包含 | B1、B2 |
| A 结论证据 | 含 A3 |
| 归纳时机 | 关闭后，不是事实数到 5 |

## 7. 风险

| 风险 | 对策 |
|---|---|
| 线索爆炸（每轮都开新） | 监控每日新增线索数；过高说明 prompt 的候选描述不够 |
| 归属错误率高 | 用 `soul_detail` 式的工具**人工改归属**（后置） |
| 归纳时上下文过大 | 线索内先压缩（只给事实 + 首尾轮次），再归纳 |
| 与 0016 的阶段冲突 | 0016 的「按事实批次归纳」作废，改为「按线索闭合归纳」 |

## 8. 实施顺序

```
1. schema v7：threads 表 + turns.thread_id（迁移，不写数据）
2. 抽取 prompt 加「线索:」行 + 解析 + 归属写入
3. 闭合器（空闲 K 轮 / 会话结束）
4. 归纳改为按线索跑（复用 0016 的两阶段）
5. 注入改为「上一闭合线索」
6. 跑验收场景
```

**每步都可单独上线**，第 1–2 步先跑几天，用真实数据看归属质量，再决定要不要调保守策略。

## 9. 验收记录（2026-11-02）

场景：`记暗号 → 问日期 → 回到暗号 → 日期收尾 → 暗号补充`，然后手动关闭线索并让它归纳。

| 检查 | 结果 |
|---|---|
| 线索归属 | A1/A2/A3 同一条线索（`#17518`、`#17541`、`#17562`），B1 独立（`#17531`） |
| 归纳时机 | 线索关闭后，非事实凑数 |
| 结论 | 「用户和助手约定「核桃」为紧急暗号，并限定只在紧急情况下、通过电话使用」 |
| 证据 | `fc_mvyk1ppj_1`（开头）、`fc_mvykjxr9_2`（回来）、`fc_mvyks7vm_3`（最后补的） |
| 判定 | **PASS** —— 结论覆盖到最后一次回来时的内容 |

复现：`node scripts/abba-check.mjs --topic <关键词>`；判定逻辑是「结论的证据里是否包含最后那一轮产生的事实」。

# 需求说明：轮与步骤（turn / step）

- 状态：Accepted（2026-11-01）
- 关联：[0010 记忆单元](0010-memory-unit.md)、[spec/model.v0](../spec/model.v0.md)

## 1. 问题

`turn_pairs(user_text, assistant_text)` 是**一问一答**：它把一轮里所有步骤的正文拼成一列，
工具调用、步骤顺序、每步在干什么全部丢失。

实测（本机 336 轮）：

| 指标 | 数值 |
|---|---|
| 平均每轮 step 数 | 5.22 |
| 有工具调用的轮次 | 237/336（70%） |
| 每步 reasoning 字符 | 846 |
| 每步工具调用数 | 1.33 |

**一轮 5 步，只有 1–2 步有正文。**只存首尾，等于只记住了结论，不知道中间做了什么、凭什么。

## 2. 决定

| 表 | 存什么 |
|---|---|
| `turns` | 一轮：谁说的、何时、`outcome`（这轮改变了什么）、`status` |
| `steps` | 轮内有序步骤：`kind`(reasoning/text/tool)、文本、工具名与参数大小、成功与否 |

- `turns.assistant_text` 保留为**去规范化的正文**（text 步骤拼接），供检索与注入——不改变读取接口。
- 重新加载时步骤按 `idx` 排序还原。
- 旧 `turn_pairs` 数据在升级时复制为 `turns` + 一条 `text` 步骤；旧表保留只读。

## 3. 不做的

- **不存推理全文**：只记字符数。理由见 RFC 0007 §5。
- **不存工具结果正文**：只记大小与成败。

## 4. 验收

```
1. 写入含 3 步（推理/工具/正文）的一轮
   → steps 按 idx 返回三类；assistant_text 只含正文
2. 用正文里的词检索
   → 能命中该轮
3. v4 库升级
   → turn_pairs 的行出现在 turns 里，且各带一条 text 步骤
```

三条均有测试（`packages/core/test/turns.test.ts`，115 项全过）。

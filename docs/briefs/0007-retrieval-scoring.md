# 需求说明：检索排序的骨架（从消费者重推）

- 状态：**Superseded（2026-11-02，→ 0019 记忆选择 + 0020 检索漏斗）**

- 后续：ADR 0010（评估口径）、ADR 0018（成长判据）、`briefs/0006`（情绪动力学）
- **起点说明**：0006 是以现有五字段为骨架改"形状"；这一份不是。它把现有字段当作历史包袱，从"消费者要做什么决定"重推。

## 1. 一句话目的

把"这条记忆该不该进注入"这件事，从**五个加权分量的经验组合**改成**三个各有指标负责的因子**，并让每一个因子都能被单独关闭做消融。

## 2. 现状与问题（实测）

> **2026-10-31 更新：`relevance` 已换成 BM25。** 本节以下的实测数据是 10-30 的记录，
> 保留原样；公式应读作 `0.35·bm25 + 0.25·importance + 0.20·recency + 0.15·vividness + 0.05·recall`。
> 权重未变，所以下面的敏感性结论仍然适用。
>
> 换算法的理由：旧 `relevance` 是纯命中比例（无 IDF、无长度归一化），而库中文档长度从 7 字到 18202 字。
> 真机 60 条记忆 / 298 条 query 实测：那条 18202 字的记忆进入 **85%** 查询的 top3、top1 平均 12150 字；
> 换 BM25 后降到 **15%**、top1 1099 字。空召回次数不变（22），不是靠少给赢的。
> 数据与复现见 [eval-longmemeval-baseline](../eval-longmemeval-baseline.md) 和 core 0.0.24。

打分公式（10-30 记录）：`0.35·relevance + 0.25·importance + 0.20·recency + 0.15·vividness + 0.05·recall`

真机 30 条活跃记忆上的实测：

| 分量 | 真机取值 | 实际贡献 |
|---|---|---|
| relevance | 随查询变化 | 0 ~ 0.35，**唯一主要信号** |
| importance | 6/7/8/9 四档 | 0.15 ~ 0.225 |
| recency | 创建时间跨度仅 24h | **0.1954 ~ 0.200**（几乎恒定） |
| vividness | 写入定 0.8/0.9，**永不变化** | 恒定偏移 0.120/0.135 |
| recall | 0 ~ 4，clamp 到 10，无衰减 | 0 ~ 0.02 |

排序敏感性（30 条记忆 × 7 个查询，只读，未改库）：

| 变体 | 平均 Kendall τ | top-5 重合 | 分数最大变化 |
|---|---|---|---|
| 去掉 vividness | 0.935 | 0.95 | 0.135（恒定） |
| recall 改衰减 | 0.936 | 0.90 | 0.032 |
| 只用 relevance + importance | 0.752 | 0.86 | 0.350 |

**结论：三个分量合起来只改变 14% 的 top-5。**

根因不是权重没调好，是**分量从哪来**：五个字段是沿袭前一个项目（soulkernel-rs）的先验，没有一个是"从消费者的决定反推"出来的。

## 3. 消费者与决定

| 消费者 | 什么时候 | 要做什么决定 | 需要什么信息 |
|---|---|---|---|
| 注入构建器 | 每轮 | 这条记忆进不进 ≤5 条、≤160 字符的预算 | 找得到吗 / 还成立吗 / 值不值得说 |
| 注入构建器（预算） | 每轮 | 给"纠正证据"留几个位置 | 当前张力（见 0006） |
| 用户 | 事后 | 为什么这条被想起来、那条没有 | `used` 列表 + 每个因子的值 |
| 评估（harness，B9） | 阶段前后 | 改了排序有没有变好 | 消融前后的 `on_pass_off_fail` |

只有四行，而现有公式要为五行乘以五个权重——**五个分量里没有一个对应"用户"那行的需要**。

## 4. 需求

| 级别 | 需求 | 验收方式 |
|---|---|---|
| **必须** | 排序由三个因子相乘构成：`相关 × 时效 × 证据` | 任一因子为 0 → 总分 0（门控），而不是被其他项顶上去 |
| **必须** | 每个因子有唯一负责指标 | 因子 ↔ 指标对照表写进 RFC，缺一行就不算完成 |
| **必须** | 每个因子可单独关闭 | 关闭后跑 harness，能产出 on/off 对比 |
| **必须** | 删掉 `vividness` | 删除后 top-5 变化 ≤5%（已实测 0.95 重合） |
| **应该** | `recall` 从"总次数"改为"近期频率"（半衰期衰减），或直接删、由 `recency` 承接 | 与现状对比 top-5 变化，写入决策记录 |
| **应该** | `validUntil` / `supersededBy` 有真实写入路径，否则删字段 | 30 天内出现非 NULL 行；否则删除 |
| **应该** | 证据等级不只用于排序，也要在**写入时**记录：这条记忆是用户原话、规则抽取、模型归纳，还是被纠正过的结论 | 每条记忆能回答"我凭什么这么确定"；写不出就是猜测 |
| **不做** | 情绪作为乘数进入排序分数 | 情绪只影响**预算分配**（张力高 → 给纠正证据多留一个位置），不改变单条记忆的排序 |

### 因子 ↔ 指标对照

| 因子 | 定义 | 负责指标 |
|---|---|---|
| 相关 | 词面/语义重叠（现 `relevance`，后接 embedding） | 判据 2「记忆真被用上」 |
| 时效 | 距上次相关事件的时间 + 是否被取代 | 判据 3「没记岔」 |
| 证据 | 纠正证据 > 用户明说 > 规则抽取 > LLM 归纳 | `repeatCorrection`（ADR 0018 主指标） |

## 5. 非目标

- 不解决"记什么"（写入侧，属于 B1/B3）
- 不解决情绪本身（0006）
- 不做向量检索（ADR 0004 零依赖约束下另议）
- 不改注入预算大小（160 字符 / 5 条）

## 6. 成功判据（可执行）

```
删除 vividness 后跑现状对照 → top-5 重合 ≥0.95（已实测，作为回归基线）
乘积形式 vs 加权和       → 构造"高相关但已失效"的用例，乘积形式必须把它排到后面
每个因子关闭一次         → 产出 3 组 on/off 对比，且每组都能归因
证据等级上线             → corrections 行数 > 0，且被纠正过的记忆排序上升
```

## 7. 前置条件与时机

- **什么时候可以实施**：S1 收尾之后。删除 `vividness` 一项因有实测支撑，可按"清死代码"提前，但需单独决定。
- **依赖**：
  1. **证据等级需要纠正数据**——`corrections` 现在是 0 行。没有它，这一因子只有两级，收益减半。所以真正的重设计排在纠正闭环之后。
  2. 需要 harness 才能做消融（B9）。
- **什么情况下不做**：如果 harness 证明"三个分量怎么改都不影响回答质量"，那就该接受"排序 ≈ 词面重叠 + importance"这个事实，把力气放回写入侧——而不是继续调权重。

## 8. 开放问题

1. 乘积形式在小样本上会不会过于激进（一个因子为 0 就整条沉底）？要不要加下限？
2. `importance` 在重设计里归到哪？它同时像"证据"又像"值不值得说"，可能该拆。
3. 证据等级的四级是拍的吗？能不能从 `corrections` 的实际形态定义，而不是先验？
4. 情绪影响预算分配时，谁来保证不挤掉锚点（importance ≥8 的常驻记忆）？
5. 这段排序将来接 embedding 时，`相关` 因子会变强，其余两个的权重该不该跟着降？

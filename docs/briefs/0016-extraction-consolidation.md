## 1. 需求

模型的产物有四样：**实体 / 事实 / 缺口 / 结论**。前三样已落库，结论层为空。

消费者只有四个问题：

| 问题 | 需要什么 | 提取（每轮） | 归纳（定期） |
|---|---|---|---|
| 她最近怎么样 | 关于她的状态与事件 | 人 + 事件 + 状态变化 | 收敛成"她当前的状态" |
| 上次为什么选 A | 决定 + 理由 | 记决定，理由引用它 | 合并成一条决策记录 |
| 不用重复交代 | 偏好 / 原则 | 抓明确表达的偏好 | 同类 ≥2 次 → 升为画像结论 |
| 答应过的事 | 承诺 + 状态 | 记承诺 | 到期未兑现 → 缺口 |

**没有归纳，提取就没有目标**：事实一直长，结论永远为空，最后还是要靠片段检索。

## 2. 文献

| 来源 | 结论 | 对我们的含义 |
|---|---|---|
| **CLS 理论**（McClelland 1995；[O'Reilly 2011 复盘](https://dev.europepmc.org/pub/databases/pmc/article-html/MED/22/1/4/1/med-22141588.html)） | 海马=快速、模式分离的情景记忆；新皮层=缓慢、重叠的整合，**通过巩固提取语义结构** | 事实层与结论层**必须分开**；巩固不是可选优化 |
| **Mem0**（[arXiv 2504.19413](https://ar5iv.labs.arxiv.org/html/2504.19413)） | 两阶段：extraction → update（LLM 选 ADD/UPDATE/DELETE/NOOP）；ASYNCHRONOUS SUMMARY 独立刷新 | 我们已有 extraction 与 supersede；**缺 update 里的"合并/升格"** |
| **Mem0g** | 冲突关系**标记无效而非删除**，以保留时间推理 | 与我们 `superseded_by` 一致，继续不物理删 |
| **Generative Agents** reflection（[说明](https://raw.githubusercontent.com/agentpatterns-ai/website/refs/heads/main/patterns/agent-design/generative-agents-memory-stream.md)） | 低层观察合成高层洞察，写回记忆流 | 归纳的产物要**写回**并参与后续使用 |
| **LongMemEval**（abstention） | 该说"不知道"时要说 | 我们的对应物是缺口：**未知是一等公民** |
| 事件分割（Zacks） | 按状态变化切分事件 | 提取以"变化"为单位，不以句子为单位 |

**边界**：CLS 是神经科学解释，不是工程处方。借它的**结构**（双系统 + 巩固），不借参数。

## 3. 边界

| 做 | 不做 |
|---|---|
| 提取判据（五条） | 端到端实体/关系抽取模型 |
| 归纳：事实 → 结论（带证据） | 一次性重写全部记忆 |
| 缺口开/合/降 | 主动发起对话（L3，宿主能力） |
| 失效用 supersede | 物理删除 |

## 4. 提取判据（每条标注来源）

1. **记变化，不记重复**——状态没变就 `supersede` 或 `noop`。（来源：事件分割 + 消费者"她最近怎么样"）
2. **记人和事，不记话题**——回答不了四个问题之一的事实不写。（来源：消费者表）
3. **决定与承诺优先**——它们是唯一能改变未来行为的东西。（来源：消费者"上次为什么""答应过什么"）
4. **不记对话动作本身**——"用户要求看源码"这类，`turns` 已存原文，事实层再存一遍就是噪声（2026-11-01 的 14 条噪声即此因）。
5. **缺口只从两处来**：用户说了"不知道/想知道"，或承诺到期未兑现。

## 5. 归纳

```
触发：每 N 轮 / 会话结束（离线；不阻塞对话）
输入：本会话新增事实 + 已有的相关结论
输出：
  - 结论（画像/教训）：一句话 + 证据 fact ids + 置信
  - 实体当前状态：从最近事实收敛
  - 缺口开合：有答案→关闭；长期没提→降张力
规则：结论可被新事实推翻（supersede）；证据缺失的结论不写
```

**结论与教训分开**（2026-10-31 已定）：画像是"你是什么样的人"，教训是"我该怎么做"。主体不同，不能混。

## 6. 与现有代码的映射

| 需要的东西 | 现状 |
|---|---|
| `facts` / `fact_slots` / `entities` / `gaps` | ✅ 已落库（schema v6） |
| 抽取（提取阶段） | ✅ core 0.0.36 + prompt v2 |
| **归纳（第二阶段）** | ❌ 完全没有 |
| `conclusions` 表 | ❌ 需要新增（或复用 `facts` + `holder=self`？待定） |

**待定项**：结论放哪。候选：① 新表 `conclusions`；② 复用 `facts`，用 `type_name='结论'` + `evidence` 槽指向事实 id。倾向 ②——少一张表，且证据关系本来就能用 `fact` 槽表达。

## 7. 声明（可证伪）

1. 一轮对话后，`facts` 新增 0–3 条，且每条能对上一个消费者问题。
2. 同一偏好出现两次，归纳后结论层出现一条带证据的结论。
3. 说"她换工作了"，旧"在职"状态被 supersede，不是两条并存。
4. 去掉归纳阶段，第三个问题（不用重复交代）永远答不出——**这是两阶段设计的必要性判据**。

## 8. 验收

| 阶段 | 验收 |
|---|---|
| A 判据上线 | 20 轮真实对话：新增 facts ≤3/轮，且无"用户要求 X"类噪声 |
| B 归纳上线 | 同一偏好两次 → 结论出现且带证据 id |
| C 拒绝测试 | 人为说一条偏好一次 → 不应升格；两次 → 应升格 |
| D 读书测试 | brief 0015 的 30 题：人物 recall ≥60%、编造率 ≤10% |

## 9. 风险

- 归纳要额外模型调用：成本随会话长度增长，需要触发节流
- 结论可能"过度概括"（两次就升格）：置信度与证据条数要一起存
- 归纳与提取共用模型额度，可能互相抢时序（见 ADR 0030 的边界）

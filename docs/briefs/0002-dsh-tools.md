# 需求说明：DSH 工具（soul_recall / soul_remember）

- 状态：Ready
- 日期：2026-10-29
- 后续：RFC 0005

---

## 1. 一句话目的

让模型在任务**中途**能主动查记忆、明确记一件事，而不是只能靠开场注入的那几条。

## 2. 消费者与决定

| 消费者 | 什么时候 | 要做什么决定 | 需要什么信息 |
|---|---|---|---|
| DSH 会话里的模型 | 用户提到过去、偏好、约定 | 要不要查、查什么 | 有没有 `soul_recall` 可调 |
| DSH 会话里的模型 | 用户说"记住…"或自己判断值得记 | 要不要写、写什么类型 | `soul_remember` 的约束 |
| 用户 | 事后检查 | 这条记忆是谁写的 | 来源（规则/模型/工具）——N2 审计 |

## 3. 需求

| 级别 | 需求 | 验收方式 |
|---|---|---|
| **必须** | `soul_recall` 返回按评分排序的记忆，**计入召回**（`recallCount++`） | 单测：调用后 `recallCount` 增加 |
| **必须** | `soul_remember` 写入前过与 `observe` 相同的闸门（shape/semantic/budget） | 单测：超长/纯标点被拒，返回原因 |
| **必须** | 两个工具失败时返回 `{ok:false, reason}`，**不抛异常** | 单测：库不可用时返回错误对象 |
| **必须** | 工具卸载时注销（`ctx.effect` + dispose） | 手工：重载后不重复注册 |
| **应该** | `soul_remember` 按内容去重（同内容不重复写） | 单测 |
| **应该** | `soul_recall` 支持 `limit`（默认 5，上限 20） | 单测 |
| **不做** | 暴露 `soul_forget` / `supersede` 给模型 | —— |
| **不做** | 让模型改情绪、改 affect | —— |

## 4. 非目标

- 不做自动调用：模型是否调用由提示词和模型判断决定（这是 MCP 给不了的"自动性"，插件也不该假装有）
- 不做写入审批流：工具写入直接生效，靠闸门 + `list`/`forget` 纠错
- 不做跨会话搜索的复杂语法（只有关键词 + 评分）

## 5. 成功判据（可执行）

```bash
# 1. 工具已注册（日志）
grep "tools registered" ~/.soulbridge/plugin.log

# 2. 真实会话里问：
#    "你把之前我说过的偏好找出来"
#    期望：模型调用 soul_recall 并返回已存策略

# 3. 真实会话里说：
#    "记住：发布窗口是每周三"
#    期望：模型调用 soul_remember，返回 id；
#          soulbridge list 能看到该条
```

## 6. 前置条件与时机

- 可以立即实施：注册方式已在 `dsh-wechat` 里验证（`ctx.inject(['tools'], …)` + `register` + `effect`）
- 依赖：core 的 `recall` / 写入闸门（已有）
- 不做的情况：如果 `tools` 服务在桌面版不可用（`ctx.inject` 失败），降级为只注入，不影响插件加载

## 7. 开放问题

1. `soul_remember` 允许写哪些类型？建议限定 `strategy|fact|trait|cognition`，与抽取闸门一致
2. 工具描述怎么写才让模型**该查时查、不该查时不查**？需要一次真实会话调优
3. 是否把 `soul_context` 也做成工具？倾向不做——开场注入由插件负责，工具会重复

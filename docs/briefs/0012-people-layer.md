## 1. 需求

用户原话：

> 我也想它能在我聊到某个人的时候，也会问一句她最近怎么样，你们还联系吗？
>
> 就像我需要认识一个新朋友一样，都是在慢慢的相处中，不同的事件中来认识对方的。

| 消费者 | 什么时候 | 要做什么决定 | 需要什么 |
|---|---|---|---|
| 模型 | 聊到某个人时 | 要不要问一句"她最近怎么样" | 这个人是谁、上次什么状态、多久没提 |
| 模型 | 同一句里的"她" | 指的是哪个人 | 指代归属（含不确定性） |
| 注入构建器 | 每轮 | 该不该把"关心一句"放进去 | 缺口张力 + 关系状态 |
| 用户 | 事后 | 它是不是真的记得这个人 | 可查的人物档案 + 事件 |

**现状**：schema 里没有任何"人"的概念；`relationship` 在 0009 被删，理由是"单用户无消费者"——**那条判断当时把 relationship 理解成了"谁共养 soul"，没有考虑"你生活里的人"**。本文推翻这个隐含结论。

## 2. 文献

| 来源 | 结论 | 对我们的含义 |
|---|---|---|
| **Fiske, Cuddy & Glick：温暖 × 能力是人物知觉的两个通用维度**（[overview](https://www.sciencedirect.com/topics/psychology/person-perception)） | 人评价他人几乎总是先落在这两轴上：对方是否善意、是否有能力 | 人物画像不要用一个笼统 `status` 字符串，至少分 **warmth** 与 **competence** 两轴；它们回答"这个人对我如何、这个人行不行" |
| **自发特质推断**（Uleman 等，[综述](https://scholar.google.com.co/citations?view_op=view_citation&hl=es&user=FVofl0sAAAAJ&sortby=pubdate&citation_for_view=FVofl0sAAAAJ:XD-hx7UXLsC)） | 听到行为会自动推断特质，且推断可在无意图时发生 | 系统可以自动从事件归纳人物特质，但要允许被后续事件推翻 |
| **特质标签 vs 具体行为证据**（[ANU 论文](https://openresearch-repository.anu.edu.au/server/api/core/bitstreams/30582504-b7b4-4023-b3a0-aa42f112d02e/content)） | 人对一个人的记忆同时包含抽象标签与个体化行为证据；标签方便预测，行为证据可修正 | **两层都要存**：少量特质结论 + 原始事件。只存标签会僵化，只存事件无法预测 |
| 关系随时间变化（联系频率、亲近度） | "还联系吗"本身就是关系状态问题，不是事实查询 | 需要 `last_mentioned_at` / `contact_state`，以及可衰减的缺口 |

**边界**：文献描述人的社会认知，不是 LLM 记忆机制。只借**结构**（双层、两轴、会更新），不借参数。

## 3. 边界

| 做 | 不做 |
|---|---|
| `people` 一等记录：称呼/别名/关系/两轴/最近提及 | 人际网络图（谁认识谁） |
| 事件挂人：`episodic.person_id` | 关系类型枚举（同事/朋友/家人之外暂不扩） |
| 指代解析：精确匹配优先，不匹配则记录"未归属提及" | 用 LLM 猜指代并直接归属 |
| 缺口绑人（她最近怎样） | 主动发起聊天（那是 L3，宿主能力） |
| 特质结论可被新事件更新 | 自动删除旧事件 |

## 4. 声明（可验证）

1. 一个人物记录由**少量稳定字段**（称呼、关系、两轴）+ **事件流**组成，两层缺一不可。
2. 首次提及即可建壳；壳可以在只知道"她"的时候存在，且不被注入追问（信息不足）。
3. 缺口的张力随时间增长，与 `last_mentioned_at` 反相关；张力最高的一条才进注入。
4. 指代无法精确匹配时，**不归属**，另记一条待确认提及；下次用户明说再回填。
5. 旧事件不删除，`status` 变化通过新事件 + 旧事实 `valid_until` 表达。

## 5. 验收

```
# 1. 建壳与填充
说"我同事小林上周被裁员了"
  → people 里出现"小林"（relation=同事），一条事件挂在她身上
  → 她的 status 记为"近期离职"

# 2. 指代
再说"她最近怎么样"
  → 能归属到小林（唯一匹配）；注入了她的状态与时间
说"我也认识一个她"（无匹配）
  → 不归属，生成待确认提及；不注入

# 3. 关心
把 last_mentioned_at 改到 10 天前、缺口张力拉高
  → 注入出现一句追问，且不编造状态

# 4. 不编
档案里没有的字段（例如年龄）
  → 回答"不知道"，不推测
```

## 6. 不做的情况

- 若指代解析的精确匹配覆盖率低于 50%（真实对话里大部分是"她/他/那个人"），
  先做**显式称呼**（名字/关系称谓）这一半，指代延后——不要用猜测硬填。

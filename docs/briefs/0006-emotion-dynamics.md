# 需求说明：情绪状态与"情绪影响什么"

- 状态：Draft
- 日期：2026-10-29
- 后续：ADR 0017（情绪如何影响行为）、ADR 0018（成长判据）、`thesis.md`（P1/P2）
- 外部参考：Generative Agents 检索分数、Sentipolis 的 PAD + 双速衰减、情感动力学 OU 模型

---

## 1. 一句话目的

让情绪状态**有方差、有回落、能被反向驱动**，并且把"情绪影响行为"落到**注入内容**这一层（而不是只换一句语气文案）。

## 2. 现状与问题（真机数据）

```
bond       = 2.00   ← clamp 上限，已饱和
tension    = 0.03
passion / selfRegard / curiosity / contentment = 0.30  ← 建库至今从未变化
corrections = 0 行
```

三个问题：

1. **状态退化**。`nextEmotion` 是单调累积：普通轮 `bond += 0.02`、`tension *= 0.85`（[reflect.ts:180-200](../../packages/core/src/reflect.ts)）。没有 home base，bond 约 85 轮后撞上限，从此恒定。
2. **更新频率与语义不符**。注释写 "an ordinary session lets tension decay"，但调用点在每轮 `observe`（`index.ts:270`），按轮而非按会话。
3. **影响的层次太浅**。情绪只经由 `context()` 的五个硬编码阈值产出一段 `style` 文案（`context.ts:24-28`），**不改检索、不改条数、不改写入**——除了措辞，系统行为完全不受影响。

后果：`bond>0.8` 永久为真 → "像朋友一样聊天"成为常量；`tension>1.0` 从未触发 → 谨慎指令从未生效。

## 3. 消费者与决定

| 消费者 | 什么时候 | 要做什么决定 | 需要什么信息 |
|---|---|---|---|
| 注入构建器 | 每轮 | 这轮注入几条、注入哪类（纠正证据 / 基础事实 / 相关经历） | 情绪状态 + 当前消息 |
| 三臂实验（ADR 0017） | P3 | 情绪是否带来可辨识的行为差异 | 三组预设情绪的注入差异 |
| 成长判据（ADR 0018） | 4 周 | 状态是否在变、还是在退化 | 每维方差、饱和时长 |
| 用户 | 事后 | 它是不是"有脾气"还是"贴了张标签" | 可读的状态轨迹 |

## 4. 需求

| 级别 | 需求 | 验收方式 |
|---|---|---|
| **必须** | 状态必须有 home base（基线）并回归到它 | 连续 200 轮无纠正后，每维回到基线 ±0.15 内 |
| **必须** | 状态必须有方差（不得长期贴 clamp 边界） | 一周内每维标准差 > 0，且无维度连续 >100 轮完全不变 |
| **必须** | 更新频率与设计语义一致（按轮 / 按会话只能选一个并写进 spec） | spec 与代码调用点一致，且有测试断言 |
| **应该** | 情绪影响注入**内容**：检索分数加一项情绪一致项，α 可调 | α=0 与 α>0 两档注入结果可 diff；`used` 可追 |
| **应该** | 采用"骨架借用、参数自定"：函数形状来自公开模型，常数由本仓库数据标定 | 每个常数在 spec 里有来源与取值范围 |
| **不做** | 完整的 ACT（affect control theory）EPA + 行为词典实现 | 行为空间是"多查一次/多问一句"，不是社交动作，硬套成本高收益不明 |

## 5. 非目标

- 不证明"AI 有情绪"（ADR 0017 的边界不变：**情绪改变怎么说，不能改变说什么**）
- 不做情绪分类精度提升（那是 B4，词表问题，另行处理）
- 不做跨用户情绪同步
- 不在 S1 观察期内实现

## 6. 骨架与参数（候选，待评审）

**骨架 A：回归到基线**

```
x(t+1) = μ + ρ·(x(t) − μ) + Σ Δk
```

`μ` 基线、`ρ` 惯性、`Δk` 事件冲量（纠正 → tension +、selfRegard −）。

**骨架 B：双速**（Sentipolis 的做法）

- 快：每轮按本轮事件小幅更新
- 慢：会话结束向基线回归并汇总

**骨架 C：窗口式**（对应"有界重放"的思路）

```
bond(t) = f(最近 w 轮的联结事件)
```

只看窗口内的证据，而不是从建库至今累积。优点：天然有界、不会饱和；缺点：会丢掉长期趋势，需要和 B 结合。

**骨架 D：情绪影响检索**

```
score = α_r·recency + α_i·importance + α_rel·relevance + α_affect·congruence
```

`congruence` = 记忆情绪标签与当前状态的相似度。四项各自 min-max 归一；`α_affect` 从 0 开始做消融。

| 参数 | 含义 | 默认值来源 |
|---|---|---|
| μ（每维） | 情绪基线 | 当前 `DEFAULT_EMOTION` |
| ρ | 惯性 | 待标定（先取 0.9~0.99） |
| Δk | 事件冲量 | 待标定（现为 +0.3 / −0.05） |
| w | 窗口轮数 | 待标定 |
| α_affect | 情绪对检索的权重 | 从 0 开始，消融定 |

## 7. 成功判据（可执行）

```
三臂注入 diff        → 高张力 / 高联结 / 基线三组产出的注入内容两两不同（不只是文案不同）
α_affect 0 vs 0.5    → used 集合有明显差异；且 repeatCorrection 不劣化
200 轮模拟           → 每维回到基线 ±0.15；无维度贴 clamp 边界
正确性护栏（ADR 0017）→ 事实题准确率跨臂差 ≤5pp
```

## 8. 前置条件与时机

- **什么时候可以实施**：S1 收尾之后。观察期内状态退化属于 bug 还是设计缺陷，需要先判定——若按 bug 处理，可只做"骨架 A + 修正频率"，不动检索。
- **依赖**：ADR 0017 的三臂协议已就绪；`measureStyle()` 已有前四项；`used` 已记录。
- **什么情况下不做**：
  - 三臂实验结果证明情绪指令对输出无可辨识影响（ADR 0017 判据 2 不达标）→ 删映射，而不是加公式
  - 模型能力过弱导致"情绪描述被当成过度表达指令"（Sentipolis 在 GPT-4o-mini 上 believability −7~−26%）→ 先只做检索侧，不做表达侧

## 9. 开放问题

1. 频率：按轮更新还是按会话？两者对 `ρ` 的标定差一个数量级。
2. 骨架 C（窗口）和骨架 A（回归）选哪个，还是组合？
3. `congruence` 怎么算：记忆只存 `valence`/`intensity` 时，用一维距离是否够？
4. 六维是否该映射到 PAD 三维后再计算？现在两套坐标并存，会不会多一层失真？
5. 情绪状态的**可读化**：要不要像 Sentipolis 那样映射到人类可读标签再注入，还是继续用指令式文案？

## 10. 有界重放：借 DeepInfer 的 YoCo 思路（待评估，不承诺）

参考：[DeepInfer](https://github.com/deepseek-ai/DeepInfer) 里 SWA 的"有界重放"——prefix cache 只命中一部分时，不重算整个前缀，**只重算最近 128 个 token**。理由不是省成本，而是：位置 i 的 query 本来只和窗口内 key 算注意力，窗口外的部分反正会被丢弃，**重放它没有任何消费者**。于是重算代价变成常数，与上下文长度无关。另有两个细节值得抄：`128 存、134 用`（多出的 6 个位置吸收投机解码的回溯边界）；以及 `yoco_equiv.py` 的两级等价性验证——L1 只比元数据（秒级、不加载权重），L2 用固定 teacher-forcing 轨迹逐元素比 logprob。

对我们的三条映射：

1. **有界化的依据是消费者带宽，不是成本。** 情绪状态的消费者只有两样：一段注入文案（预算 160 字符 / ≤2 条指令）、以及检索排序。**一条 `bond>0.8` 的指令只有 1 bit 信息量**，却用 85 轮历史去积分——精度全浪费，还饱和。历史长度应该由"输出能分辨多少"反推，而不是由"记忆能存多少"正推。
2. **近似必须可证明等价，不能只是看起来像。** 如果窗口外的历史对当前决策确实无影响，要能写成一个断言（类似 L1 元数据比对），而不是一句注释。缺这个，"有界"就退化成"拍脑袋截断"——这正是我们不接受的粗暴解法。
3. **存储粒度与使用粒度可以不同，但差值要有确定的物理原因。** `128/134` 里的 6 不是余量手感，是投机回溯的真实需求。
4. **状态是派生视图，不是真源。** KV cache 是 token 的派生数据，缺了就重算；情绪状态同理——它应该是"最近窗口事件"的纯函数，而不是一个被 `+=` 反复改写的累加器。今天 bond 饱和的根因就是把它当成了真源。改成派生后：饱和在构造上不可能发生，且天然幂等、可重建、可单测。

风险：窗口式（骨架 C）会硬性丢掉窗口外的证据。纠正证据不应该随窗口滑走——它要进慢速记忆，由骨架 A/B 的回归项承接，而不是由窗口承接。

## 0. 通用性验收线（放最前——能被证伪才算数）

```
三条并列，任一不达标 → 这一层不算做完（用户 11-10 拍板）：
  A 交代成本   跨周重复的倾向占比  24%（基线，3 周实测）→ ≤10%
  B 识别率     换会话/换工具后前 3 轮，重问已答过的事 = 0 次
  C 溯源率     它说「我记得…」时能指到具体轮次的比例 ≥90%（基线待测）

外加一条形态红线（防退化，见 §三）：
  硬场合的定义里出现中文字符常量 / includes( / 正则字面量 → health-check FAIL
```

> 为什么 A 的线不是 1 次：定线时没有基线，现在有数了。基线 **27 条跨周重复 / 112 条倾向 = 24%**（3 周，`created_at` 实测）。定 ≤1 次/4 周等于要降 36 倍，第一天就注定 FAIL——**这是我们自己的第 20 条（空样本不是判决）对自己开的一枪**。

## 1. 一句话目的

**把「记忆」从"取回条目"换成"维持一个随场合变化、随证据变准的自己"**；成长不靠加条目，靠同一条倾向的证据基数、厚度、场合分裂。

## 2. 消费者与决定

| 消费者 | 什么时候 | 要做什么决定 | 需要什么信息 |
|---|---|---|---|
| 下一轮的模型 | 每轮开口前 | 用什么语气、要不要先问、语气多松 | **关于你**的倾向（小常驻集）+ 进行中的关系/未闭合的事 |
| 下一轮的模型 | 动手前（工具调用前） | 这次操作要避开什么 | 当前动作命中的**限制性倾向**（这个工具、这个对象） |
| 抽取模型 | 离开点 | 这条倾向该加、该改、还是该拆场合 | 已有倾向 + 本次证据 + 缺席记录 |
| 你 | 每周 review | 它有没有变准 | A/B/C 三个数 + miss 明细 |

## 3. 需求

| 级别 | 需求 | 验收方式 |
|---|---|---|
| **必须** | 人格单位 = 场合 × 倾向；同一条倾向可在多场合有不同厚度 | 库里能查出一条倾向挂 ≥2 个场合且厚度不同；注入时按当前场合取对应厚度 |
| **必须** | 场合字段 = `{act, object, tool, time}` 四硬 + 一软；值来自枚举；命中 = **声明字段 ⊆ 当前字段** | 枚举值非法 → 写入拒绝并计数；子集匹配有单测 |
| **必须** | 硬场合只碰结构字段，不读话语文本 | health-check 新增一节扫描；故意写一句 `includes('改动')` → FAIL |
| **必须** | 冲突先分场合，同场合真矛盾才取代，旧条留历史 | 两条矛盾的倾向注入时不合并、不静默选一个；取代后旧条仍可 `soul_detail` |
| **必须** | 成熟度 = 四个可算的数（命中次数、独立来源轮次、被纠正次数、最近命中），模型不打分 | 给定四个数 → 厚度档位是纯函数；变异测试能红 |
| **必须** | 缺席两口径分开记账：强信号（用户明说"又说了一遍"）、弱信号（抽取时判重复，≥2 次） | 两个计数分开出现在 stats 里，不合并 |
| **必须** | 人格写入与事实抽取在**同一次调用**（离开点），不新开调用 | 一次离开点只产生一次模型调用（日志可数） |
| **应该** | 第一批只做两个注入点：开口前、动手前 | 两个点各有 trace 事件；没有第三个点偷偷上线 |
| **应该** | 现有 201 条规则降级为证据，不再作为"规则块"直接注入 | `<rules fired>` 先与常驻集并存一段时间，判 A 达标后再撤 |
| **不做** | 微调/权重、向量检索/嵌入、数值轴打分 | 见 §4 |
| **不做** | 第一批不做主动开口、不做前端/导出 UI | 主动开口单独一棵树（"该不该问"的分寸） |

## 4. 非目标（防蔓延）

- **不做"数字生命"这种目标**——它不可验收。替代的可测目标：跨会话、跨工具，还是同一个、说得出为什么的自己。
- **不做人格可视化/导出 UI**（用户 11-10 未排除，但排在第二批以后）。
- **不重写已验的管道**：原文不可变、离开点抽取、写入闸门、成本账本、20 条抽样验收——这些与人格表示不耦合，重写等于重踩坑。

## 5. 文献：别人怎么做的，我们取哪一半

四类"人格从哪来"，各有硬伤（详见对照笔记与竞品文档）：

| 类型 | 代表 | 人格存哪 | 怎么变 | 硬伤 |
|---|---|---|---|---|
| 设定卡 | SillyTavern 角色卡、Character.AI | 人写文本 + 世界书 | 人改 | 稳定但不长 |
| 常驻块 | Letta / MemGPT | 上下文 memory blocks（2–5k 字符/块，建议 5–15 块） | 模型 `replace` | 原地覆盖，**没有历史** |
| 权重 | Second Me（[arXiv 2503.08102](https://arxiv.org/abs/2503.08102)） | LoRA 适配器 | **全量重训 30–60 分钟** | 不可审计；"Me-Alignment"读码=标准 LoRA+DPO |
| 记忆流 + 反思 | Generative Agents | 事件流 + 反思摘要 | 不断追加 | 反思是摘要不是判据，容易漂移 |

**行业在解决"稳"（persona consistency / long-horizon drift），我们在解决"长"。** 这两件事在现有架构里对立：稳的手段是冻结，长的手段是重写。我们拆成两个机制——**稳由证据、撤回、场合承担；长由证据基数与厚度承担。**

取：
- Letta 的"人格可编辑、常驻、小"（不取它的覆盖语义）
- Generative Agents 的"从经历长出"（不取它的三因子打分——我们的 `recall_count` 已经是它的表亲，实测踩了 LFU 坑）
- [SillyTavern 世界书](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)的**节奏机制**：sticky（激活后保持 N 条）、cooldown（N 条内不再触发）、inclusion group（互斥）、token 预算——我们一条都没有，这是"什么时候触发"最成熟的公开实现
- 领域里的判官敏感性警告（综述痛点）→ 我们用两个判官实测自己的分类一致率（74.1%，见实验 §7）

不取：角色卡（人格是作者的不是经历的）、权重路线（不可审计）、向量检索（不可解释、要新存储）。

## 6. 唯一声明（将来落到 `config/`，现在先写在纸上）

```
SITUATION_FIELDS = [act, object, tool, time]      // 硬，四选零到四
  act      枚举：write_file | edit_code | run_command | release | install
                 | restart | migrate_db | design | review | extract | export
                 | delete | overwrite | push | reset_hard | dep_change
  object   值类：path_suffix | repo | script | field | entity_id
  tool     枚举：powershell | pnpm | npm | schtasks | sqlite | dsh_host | git
  time     值类：turn_count | idle_hours | local_hour_range
SOFT_SITUATION   模型自由文本 + 一句"该不该现在提"（不参与子集匹配，注入时由模型当场判）

IRREVERSIBLE = act ∈ {delete, overwrite, push, reset_hard, dep_change}
                                                  // act 的一个子集，唯一走 ask 拦截的一档，其余只提示

MATURITY = f(hits, distinct_source_turns, corrections, last_hit_at)   // 四个数，纯函数
  → 厚度档：0 带证据 / 1 一句处方 / 2 半句或并入更抽象的一条
  → 降级：last_hit 超过窗口且 hits 不增

METRICS = { restate_rate, identify_rate, trace_rate }   // 三条并列，分开计
MISS_SIGNALS = { explicit_restate, model_judged_repeat(≥2) }             // 分开计，不合并
```

**存储**：复用 `facts`（`role='disposition'`）+ 槽 `场合`（结构化 JSON）、`目录句`、`依据`。不新表、不升 schema——读写按 role 过滤是加法。**理由**：facts 已经有 supersede、时间轴、来源轮次、证据链，新表会重建一遍这些语义。

## 7. 机制（四条，缺一条就退回原样）

**① 注入按"点"，触发按"场合"。**
代码只认注入点（宿主事件），记忆自己声明场合，模型当场判要不要展开。

| 注入点 | 取什么 | 判据 | 失败长什么样 |
|---|---|---|---|
| 开口前（每轮） | 关于你（无法条件化的倾向）+ 未闭合的事 | 常驻集，按成熟度控厚度 | 全是"边界"没有"在意"，读起来像说明书 |
| 动手前（工具调用时） | 当前动作命中的限制性倾向 | 子集匹配（声明 ⊆ 当前） | 场合写太窄 → 漏；太宽 → 墙纸 |

**"动手前"到底能提前多少**（已查实，见 §11）：宿主有 `tools/pre-execute`、`tools/execute`、`tools/post-execute` 三个 waterfall，`pre-execute` 看得到工具名与参数，还能 `ask`（同步等用户）。但**从它带出的文本落在本步工具结果之后**，模型是在**下一次动手前**读到。所以：

| 想要的效果 | 能用什么 | 代价 |
|---|---|---|
| 同会话里第二刀起被提醒（主用） | `pre-execute` 带 context | 零打断；第一刀拦不住 |
| 第一刀就要拦下 | `pre-execute` 返回 `ask` / `ctx.tools.guard()` | 打断一次、可能多耗一轮 |
| 动手前就说 | `agent/pre-step` 常驻集 | 不知道要动什么，只能按会话状态猜 |

第一批按第一行做；第二行只留给不可逆动作（删、覆写、`git push`），清单进 §6 枚举。

**② 厚度随成熟度呼吸**（不是随"N 条配额"）。新领域先厚，熟了自然薄；熟到极致并入更抽象的一条。
**③ 冲突分场合，不覆盖。** 同场合真矛盾才取代，旧条留历史（可 `soul_detail`）。
**④ 缺席是燃料。** 强/弱两口径分开记，欠账驱动升降，而不是靠"被命中次数"（那正是 163 条 `rc=0` 的来源）。

```

第 5 步  离开点抽取同时产"倾向修改建议"（同一次调用，不新开）
```

## 9. 验收（三条线 + 怎么测）

| 指标 | 定义 | 基线 | 首批线 |
|---|---|---|---|
| A 交代成本 | 跨周重复的倾向条数 / 倾向总数 | **24%**（27/112，3 周） | ≤10% |
| B 识别率 | 新会话前 3 轮里，重问已答过事实的次数 | 未测 | 先测 10 次换会话的基线 |
| C 溯源率 | "我记得…"类陈述中能指到具体轮次的比例 | `soul_detail` 0 次 → 近似 0 | 先测 20 条抽样 |

测法初稿：
- **A**：`scripts/rule-compression.mjs` 已有族与日期；加一段"跨周重复率"即可复算。
- **B**：固定问句集（10 条已知事实），每次换会话问 3 条；记"它答对 / 它重问 / 它编"。
- **C**：抽出 20 条"我记得…"陈述，人判能否指到轮次（用现成的 20 条抽样协议，✗≥4 改来源）。

## 11. 开放问题

- ~~**DSH 有没有"工具调用前"的钩子**~~ **已查实（2026-11-10，读 `app.asar` 内宿主文档）**：有，而且是三个。可挂的 waterfall 全集 = `agent/pre-step`、`agent/request`、`llm/stream`、`tools/pre-execute`、`tools/execute`、`tools/post-execute`；观察结果用 `tools/result`；同步拒绝用 `ctx.tools.guard()`；给某个 agent 减工具用 `ctx.tools.restrict()`；每 agent 注入有稳定 API `agent.inject()`（记 `agent/inbox/spliced`，进下一个被接纳的 step）。
  - **限制**：这些点带出的文本一律以注入 `user/message` 的形式落在**本步工具结果之后**——挡不住"这一刀"，只能影响"下一刀"。真要挡，只能 `ask`（等用户）或 guard 拒绝。
  - **顺带核对**：重写 `agent/pre-step` 决定必须展开原决定（`{...decision, messages}`），否则丢 `startsRequestSeries` 一类字段；我们插件已是对的（`index.js:1618`）。
  - **另一个约束**：不得新增 session 事件类型；`plugin:` 记录只给 DSH 实验包。我们的数据在自己的 SQLite 里，本来就不碰这条。
- **压缩可观测**：已解——`compaction/start` / `compaction/end` 在事件流里（账本已在用），离开点不止会话结束一个。
- **软场合占多数怎么办**：如果四硬字段表达不了大多数记忆，说明字段集错了；判定线 = 抽样 20 条，硬场合覆盖率 <60% 就回炉。
- **底层一致性**：`<rules fired>` 与常驻集并存期间，同一条原则可能被两处注入——需要一条"重复注入计数"，否则 A 指标会被自己污染。

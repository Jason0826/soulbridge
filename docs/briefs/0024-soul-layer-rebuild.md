# 0024 从构想向下重排：soul 层应该长什么样

- 状态：**探索中**（先定形状，不写代码）
- 日期：2026-11-03
- 上级判据：[thesis.md](../thesis.md)（记忆不是容量，是人格）
- 由来：连续几轮都在"发现一个问题 → 修一个点 → 部署 → 等重启"。每一步都对，但系统是叠出来的。
  这篇反过来：**先写清楚它该是什么，再决定现有代码哪些留、哪些退、哪些补。**

## 1. 需求：它要回答的是什么

不是"存了多少"，是**下面这些问句能不能被回答**（按消费者列，不按模块列）：

| # | 消费者问句 | 需要的东西 |
|---|---|---|
| 1 | 上次我们聊到哪了 | 上一闭合线索 + 结论 + 双方末几轮 |
| 2 | 她最近怎么样 | 人物 + 状态变化 + 时间 + 未闭合缺口 |
| 3 | 你记得我讨厌什么吗 | 关于用户的判断（画像级），不是片段 |
| 4 | 你上次为什么建议 A | 我自己的判断 + 理由（自我层） |
| 5 | 你答应过我什么 | 自我承诺 + 兑现状态 |
| 6 | 这件事我们定过吗 | 决定 + 证据轮次 |
| 7 | 换工具还记得吗 | 可携带的画像与规则，不依赖宿主 |

**判据**：一个新机制如果不能让上面任何一条变好，就不做。这是 thesis 那句"答不上来就删"的工程版。

## 2. 记忆模型：五层 + 一条时间轴

```
原始层  turns（双方原文 + 步骤）        不可变，唯一事实来源
事实层  facts + fact_slots              谁、对谁、何时、依据哪轮
线索层  threads                         跨中断的章节；默认继续
判断层  conclusions                     一句话判断 + 证据（可被取代）
自我层  self facts                      承诺/决定/教训（我这一侧）
画像层  profile                         对"你"的判断，按维度合并，≤8 条
```

每一层只有一个**产生者**、一个**单位**、一个**消费者**：

| 层 | 产生者 | 单位 | 进入条件 | 退出条件 | 消费者 |
|---|---|---|---|---|---|
| 原始 | 代码 | 一轮 | 轮次结束 | 永不删 | 抽取、归纳、自省 |
| 事实 | 模型 + 闸门 | 一轮 | 有实体或时间锚 | 被取代（supersede） | 检索、归纳 |
| 线索 | 模型判归属 | 一轮 | 默认继续 | 空闲轮数/时间 | 归纳、handoff |
| 判断 | 模型 + 双阶段验证 | 一条线索 | ≥2 条证据 | 被更好的判断取代 | 注入、画像 |
| 自我 | 模型（我的承诺/决定）+ 纠正 | 一条 | 带依据 | 兑现或作废 | 注入、复核 |
| 画像 | 模型合并 + 维度准入 | 一个维度 | 同类 ≥2 条 | 被新合并取代 | 每轮常驻 |

**关键约束（今天的教训直接写进来）**：
- 每层必须能回答"谁读它"。**写了没人读的字段，就是债**（holder、依据、承诺都曾是这样）。
- 每层只有一个写入者；排队的工作不允许被第二个写入者绕过（第 41 条）。
- 判断类写入必须带证据 id；证据解析不到就不写（可归因）。

## 2.5 两个正交的轴（不要混成一个）

上面的五层是**加工阶段**（一条信息走到哪一步）。昨天定的是另一件事：**成立位置**（这条事实在哪里成立）。两者不是替代关系，是同一条事实的两个坐标。

**轴 A｜成立位置**（ADR 0032，昨天）：`world`（世界）/ `self` 或某人在其心里 / **`gap`（落差：期待与事实不一致）**
**轴 B｜加工阶段**（本文 §2）：`turn → fact → thread → conclusion → profile`（+ self 作为 fact 的一种）

| 事实 | 位置（轴 A） | 阶段（轴 B） | 消费者 |
|---|---|---|---|
| 小林在 2026-10-24 被裁员 | world | fact | 检索"她最近怎么样" |
| 你担心她撑不住 | 你的心里（entity） | fact | 检索、关心 |
| 她没来上班 | **gap**（世界不成立、你的期待里成立） | fact + gap | 主动问 |
| 我答应明天补表 | self | fact（承诺） | 兑现复核 |
| 你在意"先验证再动手" | self（画像持有） | conclusion → profile | 每轮常驻 |

**修正**：上一版把 `gap` 写成了"缺口表"，没有放回模型里——这是漏的。**落差是第三类成立位置**，不是附属数据；"她最近怎么样"能问出来，靠的就是它。

## 3. 阶段契约（输入 / 输出 / 失败）

| 阶段 | 输入（整单位） | 输出 | 失败语义 |
|---|---|---|---|
| 记录 | 一轮（双方） | turns/steps | 写失败必须报，不静默 |
| 抽取 | 整轮 + 上一轮 + 候选线索近轮 | facts + 归属 | 模型失败保留重试；空回答 ≠ 无事实 |
| 归属 | 整轮 + 候选线索 | thread_id + 理由 | 拿不准接最近一条（ADR 0034） |
| 归纳 | 整条线索（双方原文 + 事实） | 结论 + 证据 | 证据 <2 条不归纳，记原因 |
| 归类 | 一条判断 | 规则（触发+动作）/ 画像（维度） | 分不出进"待修"，不硬塞 |
| 注入 | 当前轮 + 状态 | 块（soul/style/规则/画像/记忆/handoff） | 无内容就不注入，不编 |

**一条判断只开一次调用**（第 39 条）：新增判断先并进已有调用。今天的七个 prompt 出口就是反面教材。

## 4. 文献：借什么、不借什么

| 来源 | 借 | 不借 |
|---|---|---|
| Generative Agents（Park 2023） | 观察→反思→计划的层级 | 它的重要度打分表（语义归模型） |
| CoALA（Sumers 2023） | 工作记忆/长期记忆/程序的划分 | 它的固定分类枚举 |
| MemGPT/Letta | 分层上下文与主动取用 | 它的工具式内存管理（绑宿主） |
| Mem0 | add/update/noop 的合并语义 | 向量优先的检索入口 |
| LongMemEval | 跨会话问答的评测口径 | 单一指标论 |
| Conversation Disentanglement（Kummerfeld 2019） | 线索可交织、可不相邻 | 它的切分算法（我们按归属而非切分） |
| AGM 信念修正 | 取代 / 收缩 | 形式化全套 |
| NLI 三分 | "否定" ≠ "错误" | 用它判对错 |
| AIS（可归因） | 结论必须挂证据 | — |
| McAdams 叙事同一性 | 人格来自串联经历的故事 | 心理学量表的条目 |
| Metzinger 自我模型 | "我"是一个模型，记我说的/答应的/错的 | 现象意识的主张 |

**边界**：文献给原理与验证方法，不给操作清单。六种合并操作、四关验收这些是我们的工程规则，不是论文结论。

## 5. 边界：明确不做

- 不做向量库（可接索引，但不做入口）
- 不做多租户/云端（单 soul 单库）
- 不追间接关系（只走一跳）
- 不把 reasoning 注入（可存、只自省）
- 不在提示词里写常驻长文（规则要触发，画像要合并）
- 不重写 sqlite（schema 可改，引擎不换）

## 6. 与现状的差异：留 / 退 / 补

**留**（今天验证过是对的）：
```

**退**（旧表示）：

```

**补**（今天没有的）：
```

行为层：规则触发 → 注入 → 遵守率（L3 闭环）
导出：可携带文件（画像 + 规则 + 承诺）
```

## 7. 验收（沿用已有数字，不再新造）

```
归属：≥90% 每轮；≥2 轮线索 >50%（ADR 0034）
归纳：每 10 条关闭线索 ≥5 条结论；证据可追溯 100%
画像：≤8 条，覆盖 ≥5/7 维，可追溯
行为：规则触发有日志；遵守率可算
可携带：换宿主后，画像与规则无需重新交代（P3）
```

## 9. 需要你定的五个问题

1. **核心单位是"人"还是"事"？** 现在的模型以事实/线索为中心；如果伴的核心是"你和你关心的人"，画像与人物层要提到事实层之上。
2. **情绪进不进记忆模型？** 现在有 affect_samples 但不参与任何判断。要么让它影响行为（触发条件），要么从模型里删掉。
3. **可携带带什么？** 只带画像+规则（轻），还是连对话原文（重、隐私）。
4. **要不要多 soul？** 单 soul 的话，作用域检查可以先不做（P0 的 id 越权只影响多 soul）。
5. **读书验收现在做吗？** 它是唯一能测"跨会话理解"的端到端实验，但要先有干净的模型。

### 补充：教训的 scope 与衰减（昨天定过，本文漏写）

教训独立于画像（"我该怎么做事" vs "你是什么样的人"）。它有两个昨天定过、本文 §2 没写的属性：

```
scope   全局（换项目也成立，如"Set-Content 会写 BOM"）
        项目级（本项目阶段有效，如"MVP1 只修 bug"）
decay   由后果强度与复现频率决定，不一律常驻
```

现在的实现是临时做法：`type_name=教训` + 高置信，进锚点，不分 scope、不衰减。
**记在这里，避免下一次又被当成"永久 L0"。**
## 10. 决议（2026-11-03）

| # | 问题 | 决定 | 后果 |
|---|---|---|---|
| 1 | 核心单位：人 vs 事 | **两者都是**，不由领域分核心 | 领域做成模型写的槽位（`域=工作/生活/两者`），代码只用于检索排序；核心由"消费者问句"决定 |
| 2 | 情绪进不进模型 | **进**，且必须影响行为 | 情绪是状态（affect_samples），消费者是规则触发（阈值→动作→遵守率），不进 facts |
| 3 | 可携带带什么 | **档案（全库，含原文）默认带上**；摘要（画像+规则+承诺+偏好）给人读和冷启动；注入只是"这一轮带什么" | 原设计把三者混成"导出不含原文"是错的——换宿主不该丢记忆，只该丢上下文预算 |
| 4 | 多 soul | **不做** | 作用域越权检查推迟；`soul_id` 列保留不动 |
| 5 | 读书验收 | **闭环可用后**再做 | 门槛：A/B/C 三场景在真实对话里通过 + 归纳真的在跑 |

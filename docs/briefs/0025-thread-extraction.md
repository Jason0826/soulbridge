# 0025 主题级抽取：以线索为单位，事实必须自包含

> 状态：已定（2026-11-04）。取代「每轮抽一次」的做法。
> 触发：用户指出“一个主题里的对话要综合起来看，而不是每句话抽一条”。

## 一、问题（实测）

```
逐轮抽取：每轮一次调用，输入是上一轮的问答
线索：只在关闭时用于归纳结论，从未用于“理解一个主题”
结果：33 条 active 事实带实体槽，但陈述里没有该实体名
      例："10-24 被裁员"（谁？）· "MVP1 阶段不存推理…"（关于谁？）
```

指代（“她”“那天”）在单轮里无解；状态和结束它的事件被拆成两条互不关联的记录。

## 二、决定

**抽取的单位是线索（主题），不是轮次。**

```
一条线索关闭（或到增量上限）
  → 把线索内全部轮次按时间顺序作为一次输入
  → 模型输出自包含事实："小林 2020 年入职 A 公司"、"小林 2024-10-24 被裁员"
  → 同一状态的多句话合并为一条，事件单独成条
```

“自包含”指：**陈述离开对话也能被读懂**——主体用名字，时间用绝对日期。

## 三、触发与上限

| 情况 | 行为 |
|---|---|
| 线索关闭（归档 / 走够轮数 / 静默 24h） | 入队抽取 |
| 线索仍开着、但已累计 ≥6 轮自上次抽取 | 入队一次（增量），避免长会话在关闭前完全没有记忆 |
| 同一线索已在队列 | 不重复入队（合并） |
| 队列上限 | 沿用现有上限；丢弃时记数 |

## 四、输入形态

```
<thread topic="…">
  <turn n="1" at="2026-10-20">用户：… ｜ 我：…</turn>
  <turn n="2" at="2026-10-24">用户：… ｜ 我：…</turn>
</thread>
<known-entities>…</known-entities>
<known-facts>…</known-facts>
```

轮次文本是完整单位（不截半句）；assistant 侧仍只给正文，不含推理。

## 五、守则（写进 prompt + 代码闸门）

1. 事实必须自包含：陈述里出现主体名（本条线索涉及的实体）。
2. 时间必须是绝对日期；原文说法保留在「时间原文」。
3. 同一主体的状态变化：新状态一条（带开始），结束它的事件一条；不要写“10-24 被裁员”。
4. 跨轮重复的话只留一条；补充信息合并。
5. **代码闸门**：事实带实体槽、但陈述不含该实体名 → 拒绝该条并计数（`self-contained-rejected`），不静默写入。

## 六、即时回忆怎么办

主题级抽取在关闭/增量点才产事实，会话中段可能还没有新事实。兜底是**原文片段**（现有 `<related>` 与最近轮次），不新增第二条抽取管线。

## 七、影响面

- 队列项从 `turnId` 变为 `threadId`（旧的按轮任务在升级时丢弃并记数，不假装执行）；
- `renderExtractionPrompt` 增加 thread 形态输入；旧单轮形态删除，不留两条路径；
- 抽取调用次数下降（每线索一次 vs 每轮一次），单次输入变大；
- `commitDrafts` 不变；自包含闸门放在提交前。

## 八、验收

用真实线索重放（如「核桃」线）：

```
① 每条事实单独读，主体与时间都明确
② "入职 A 公司" 与 "10-24 被裁员" 在同一人的时间线上，前者 valid_until=10-24
③ 不再产生裸主语事实（计数 0）
④ 同一条线索不重复抽取（队列里只有一项）
```

四项都过才算完成；任一项不过，改 prompt 或闸门，不靠解释。

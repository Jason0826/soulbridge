# 需求说明：读书验证（book recall）

- 状态：Draft
- 日期：2026-11-01
- 关联：[model.v0](../spec/model.v0.md)、[ADR 0028](../adr/0028-storage-and-recall.md)、[0012 人物层](0012-people-layer.md)
- 前置：`entities / facts / fact_slots / gaps` 已实现（主线）

---

## 1. 要验证什么

**记忆层能不能只靠库里的事实，回答一个它在"读"的时候就再也看不到原文的世界。**

这是事实层的端到端验收，覆盖：实体识别与消解、事件与时间、状态变化、人物关系、跨会话召回。

## 2. 设计

```
读：一本书 → 切段 → 抽取（实体/事实/槽位）→ 写入，原文不注入
问：新开会话 → 问人物/事件/关系 → 只靠记忆回答
判：逐题对照原文，分三种结果
```

**关键约束**：问的时候不允许把原文放进上下文。否则测的是长上下文，不是记忆。

## 3. 选书

| 项 | 选择 | 理由 |
|---|---|---|
| 书 | 《阿Q正传》（约 2 万字，公版） | 人物密度高（阿Q、赵太爷、吴妈、小D、王胡）、事件成链、有状态变化（从雇工到被枪毙）、关系复杂 |
| 规模 | 首轮只跑这一篇 | 跑通再上长篇 |
| 切段 | 800–1200 字/段，约 20–25 段 | 与注入预算无关，是为了抽取质量 |

## 4. 问题集（30 题）

| 类别 | 数量 | 例子 |
|---|---|---|
| **人物** | 10 | 阿Q 是谁？他和赵太爷什么关系？吴妈在他生活里是什么角色？ |
| **事件** | 10 | 阿Q 为什么被打？他最后怎么了？"革命"那件事他怎么参与的？ |
| **关系** | 10 | 谁看不起阿Q？他和谁起过冲突？为什么小D被他瞧不起？ |

每题标注：**答案出处段落**（用于判定是否可追溯）。

## 5. 判分

| 结果 | 定义 |
|---|---|
| **对** | 关键事实与人名正确，且不冲突于原文 |
| **错** | 与原文矛盾 |
| **不知道** | 明确说不知道，或答案不含关键信息 |
| **编造** | 给出的细节在原文不存在（无论听起来多合理）——**单独统计** |

## 6. 指标与门槛

| 指标 | 门槛 | 说明 |
|---|---|---|
| 人物 recall | ≥ 60% | 书的角色是有限的枚举，可人工定真值 |
| 事件 recall | ≥ 50% | |
| 关系 recall | ≥ 50% | |
| **编造率** | **≤ 10%** | 硬门槛：宁可不知道，不可编 |
| 可追溯率 | ≥ 80% | 答案能指回具体事实/段落 |

任一项不达标 → 不进入 MVP2。

## 7. 成本

- 抽取：约 25 段 × 1 次 LLM = 25 次调用
- 判分：30 题 × 1 次裁判 = 30 次（可用人工抽检替代）
- 单次实验约 50–60 次调用，可接受

## 8. 反作弊

1. 提问会话**不注入原文**，只注入记忆层检索结果
2. 题库固定，跑之前不调整
3. 判分用独立裁判（人工或另一模型），自评不算
4. 编造单独统计，不能被"答得多"稀释

## 9. 与主线的顺序

```
1. entities / facts / fact_slots / gaps 落库
2. 抽取器（先规则 + LLM 兜底，复用现有 observe 路径）
3. 跑第一遍读书 → 拿到基线
4. 调抽取/召回 → 再跑，看变化
```

## 10. 明确不做的

- 不做全文问答（那是长上下文，不是记忆）
- 不做多本书同时（一次一本书，变量单一）
- 不追求高 recall 掩盖编造——**编造率是一票否决**

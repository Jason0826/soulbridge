# 需求说明：注入 trace（T1）

- 状态：Draft
- 日期：2026-10-31
- 关联：RFC 0006（pre-step 注入）、RFC 0007（turn_pairs）

---

## 1. 一句话目的

每次注入都留下一条**可对账的结构化记录**，回答"这条记忆为什么进了 prompt / 为什么没进"。

现在只有一行文本日志：`prestep: inject turn=157 chars=83 ids=[tp_…]`。
它告诉了我们**结果**，没告诉我们**过程**——候选有多少、分数多少、被谁挤掉。

## 2. 消费者与决定

| 消费者 | 什么时候 | 要做什么决定 | 需要什么信息 |
|---|---|---|---|
| 我（排障） | 发现"该记住的没注入" | 是召回没命中，还是分数低，还是被截断 | 候选数、分数、丢弃原因 |
| 你（审计） | 怀疑它记错了/忘得快 | 这次注入的依据是什么 | 同上的精简版 |
| 未来的评估脚本 | 对照实验 | 改排序前后差异 | 机器可读的 jsonl |

## 3. 现状缺口（已核实）

| 事实 | 位置 |
|---|---|
| 召回只返回 pair，**分数在 filter 后被丢弃** | `sqlite.ts:537-543` |
| 注入日志只有 `chars` 和 `ids` | 插件 `index.js:297` |
| 丢弃原因不可见：`score<=0`、超出读取窗口、DB 异常，三者无法区分 | 同上 |

## 4. 需求

| 级别 | 需求 | 验收方式 |
|---|---|---|
| **必须** | 每次注入写一条 jsonl 记录：时间、turn、字符数、候选数、命中数、注入 ids | 看 `trace.jsonl` 字段齐全 |
| **必须** | 记录分数（至少前 N 条的 id + score） | 记录里能看到排序依据 |
| **必须** | 区分丢弃原因：`notRelated`（score≤0）/ `overWindow`（超出读取窗口） | 两个字段都能非零 |
| **必须** | **默认不写原文**，只写 id / 长度 / 哈希 | 文本中搜不到用户原话 |
| **应该** | 写入侧也记一条（草稿 → 闸门 → 落库） | `event:"write"` 记录存在 |
| **不做** | trace 参与召回、被注入、影响行为 | 关掉 trace 后行为完全一致 |
| **不做** | 图形界面 | —— |

## 5. 非目标

- 不做可视化时间线
- 不做跨设备同步
- 不记录完整 prompt（太大，且原文敏感）

## 6. 成功判据（可执行）

```bash
# 1. 发一句相关的话
# 2. 看 trace
tail -1 ~/.soulbridge/trace.jsonl
# 期望：{"ts":…,"event":"inject","turn":N,"chars":…,"candidates":…,"related":…,"ids":[…],"dropped":{"notRelated":…,"overWindow":…},"scores":{…}}
# 3. 原文不外泄
grep -c "<刚发的原话>" ~/.soulbridge/trace.jsonl   # 期望 0
# 4. 关闭开关
# traceEnabled:false 后不再新增记录，注入行为不变
```

## 7. 前置条件与时机

- **需要 core 小改**：召回要能把分数带出来（现在丢弃）。
  最小改动：`recallTurnPairs` 增加可选的详细返回，或在 `TurnPairSpec` 里加 `withScores`。
- 插件负责落盘到 `~/.soulbridge/trace.jsonl`（core 不做 I/O）
- 可以立即实施；不影响现有行为

## 8. 开放问题

1. **轮转**：按大小（10MB × 3 份）还是按天？倾向按大小，按天会丢"昨天那次异常"。
2. **范围**：T1 只做注入；写入侧（T2）这次一起做，还是分开？
3. **query**：要不要记录查询文本的哈希，用于判断"同一句话两次召回结果不同"？
4. **采样**：每轮都记会不会太大？按现在频率（每轮一条），一天几百条、几十 KB，不需要采样。

# RFC 0001：基础设计

- 状态：Accepted
- 日期：2026-10-27
- 关联：ADR 0001–0011、`docs/spec/protocol.v0.md`

---

## 1. 问题

每个 agent 工具都有自己的记忆：Claude Code 记得 Claude Code 里的对话，Cursor 不记得，Pi 也不记得。用户换一个工具，偏好、判断、被纠正过的错，全部归零。

这不是"记忆不够多"的问题——是**没有任何一层属于用户、而不属于某个工具**。

## 2. 定位

> 给任何 agent 装上一个人格层：跨工具记得你、会忘记、会成长。

它**是**：一个旁挂进程（CLI / 本地服务），由宿主在四个时机调用。

它**不是**：agent runtime、向量数据库、SaaS 记忆服务、表达训练工具。

## 3. 用户

| 用户 | 诉求 | 是否 v0 服务 |
|---|---|---|
| 同时用多个 agent 工具的开发者 | 不想每次重新解释自己 | ✅ 主用户 |
| 想给 agent 加"连续性"的产品团队 | 可嵌入的人格层 | ✅ 通过 MCP/hooks（v0.2+） |
| 研究者 | 可复现的记忆评估方法 | ✅ eval 公开 |
| 普通消费者 | 一键安装 | ⚠️ 只在 T0 形态下可用 |

## 4. 非目标

- 不做 agent loop、工具执行、TUI
- 不做内容检索引擎（ADR 0009）
- 不做云端服务、不做多租户计费
- 不做"有意识/自主目标"这类不可验证的特性

## 5. 成功指标

**产品侧**

1. 陌生人在 60 秒内装好并看到一次"它记得我"
2. 连续使用两周后，用户主观上不愿关掉它

**工程侧**（ADR 0011 门禁）

1. `npx` 冷启动 < 300ms；单轮分析 < 5ms
2. 零运行时依赖；core < 3000 行
3. 每条注入可审计（`used`）

**假设侧**（ADR 0010）

1. v0.1 单臂评估：有 soul 组的重复提问/重复犯错率显著低于无 soul 组
2. P3 四臂：人格层的收益不随上下文窗口增大而消失（thesis P1）

## 6. 系统形态

```
宿主（DSH / Claude Code / Pi / Cursor / Codex）
   │  T0: 指令 + CLI   T1: transcript 摄取   T2: hooks   T3: MCP
   ▼
soulkit（本地进程）
   ├── core：人格状态 · 打分 · 注入 · 反思   （零依赖，纯函数优先）
   └── SQLite：~/.soulkit/soul.db
```

## 7. 四个动词

| 动词 | 何时 | 输出约束 |
|---|---|---|
| `context` | 会话开始 | ≤ `maxChars`；只丢弃不截断；返回 `used` |
| `observe` | 每轮 | 同步、无模型、<5ms、永不抛 |
| `recall` | 需要时 | 调一次即计数一次 |
| `reflect` | 会话结束 | 无模型时降级为规则抽取 |

完整 schema 见 `docs/spec/protocol.v0.md`。

## 8. 接入阶梯

T0（指令 + CLI）→ T1（transcript）→ T2（hooks）→ T3（MCP）。
v0.1 只做 T0 + T1，验证宿主是 DSH，发布宿主是 Claude Code。见 ADR 0007。

## 9. 未决问题

| 问题 | 影响 | 计划 |
|---|---|---|
| 命名（`soulkit` 是工作名） | 发布前必须确定 | P1 前 |
| 完整 LICENSE 文本 | 没有它不算开源 | 发布前 P0 |
| 中文分词质量（无依赖，最大正向匹配） | 影响召回 | v0.1 用评测验证 |
| 多用户/多人共享一个 soul | 决定 schema 是否要 `user_id` | 已有字段，v0 只做单用户验证 |
| 宿主原生提供跨工具记忆 | 项目可能失去位置 | 写进放弃条件 |

## 10. 放弃条件

1. v0.1 单臂评估显示无任何行为差异
2. 第二个宿主接入需要改核心（抽象失败）
3. 宿主平台原生提供跨工具的人格层
4. 连续三个月没有外部使用者

# RFC 0002：输入侧情感层（affect）

- 状态：Accepted
- 日期：2026-10-28
- 关联：ADR 0012–0019、`docs/spec/affect.v0.md`

---

## 1. 为什么要做

soulbridge 现在只懂**自己的**状态（身份、情绪、记忆），对**用户这一侧**几乎无感知：用户是烦躁、是敷衍、还是在耐心解释，系统一律当作同样的输入。

这带来两个具体问题：

1. **注入没有分寸**：同一个 soul 对疲惫的用户和兴奋的用户说同样的话。
2. **评估缺一半**：成长实验要测"重复犯错"，但"用户当下的表达"是解释这些数字的重要变量，现在完全没采集。

## 2. 关键区分：两套情绪

| | SoulEmotion（已有） | UserAffect（新增） |
|---|---|---|
| 回答的问题 | 我现在的状态 | 用户这句话表达了什么 |
| 形状 | 6 个连续维度 | 7 类 + 强度 1–9 + 极性 + 证据词 |
| 时间尺度 | 天/周基线 | 单轮瞬时 |
| 证据 | 不需要 | 必须有（否则不可审计） |
| 消费者 | 风格指令 | 风格指令 + 采样（供评估） |

**v0 不做桥接**：affect 不写 `Emotion`。理由见 ADR 0012——"用户生气我也紧张"是一个未经测量的假设，不能先于证据实现。

## 3. 数据流

```
user turn
  │
  ├─▶ analyzeAffect(text) ──▶ AffectSignal
  │                              ├─▶ selectDirectives() ──▶ <affect> 注入（白名单，≤2 条）
  │                              └─▶ saveAffect()        ──▶ affect_samples（30 天，供 P3）
  │
  └─▶ nextEmotion(turn) ──▶ Emotion（与 affect 无关，T10 钉死）
```

## 4. 范围

**做**：规则分析器（8 条规则）、可替换的分析器端口、可选 LLM 适配器（默认关）、五条白名单注入、60 条黄金集（40 dev + 20 holdout）、采样落库。

**不做**：affect → Emotion 桥接、affect 调记忆权重、训练分类器、多语言、反讽专项。

## 5. 成功标准

1. dev 基础桶 ≥95%，holdout 基础桶 ≥90%，两者差距 ≤10 点
2. 规则 ≤8 条、种子词 ≤120
3. 注入只可能来自 5 条白名单；`confidence < 0.6` 不注入
4. `Emotion` 六维与 affect 无关（回归测试）
5. 落库只有词条与计数，无原句

## 6. 已知局限（写下来，不假装）

- **反讽识别不了**："太好了，又崩了" 会被判为无情绪（我们选择沉默，而不是猜错）
- **否定只能看窗口**："不得不开心" 这类双重否定会判错
- **holdout 仍由作者编写**：它能防"边改边看"，防不了"同一作者拟合"。真正的检验要用 P3 的真实转写补测
- **中文限定**：`lang` 字段已预留，英文留到 v1

## 7. 与后续阶段的关系

| 阶段 | 内容 |
|---|---|
| R2（本 RFC） | 分析、注入、采样、测量工具、预注册表 |
| P3 | 情绪→行为三臂实验、成长双 soul 实验（ADR 0017 / 0018） |

# 改动清单（每次改动过一遍）

> 规范在 [process.md](process.md)（十步），代码要求见 [code-quality.md](code-quality.md)。
> **这份是操作版**：从上面两份里挑出每次都要确认的，按改动大小分两档。
> 用它的目的不是走流程，是**避免"跑通就算完成"**——今晚 40 个问题全是这么漏掉的。

## 交付说明模板（每次改动的第一条消息就写这个）

```
为什么改：   （问题是什么，证据）
怎么做：     （改哪几个文件，为什么是这里）
影响面：     （哪些行为/数据/指标会变；哪些不变）
怎么验：     （跑什么命令；预期看到什么）
```

没有"影响面"那条的改动，一律不开始。

## A. 任何改动（包括改一行）

| # | 问自己 | 算过 | 证据（贴出来） |
|---|---|---|---|
| A1 | 我说清为什么了吗 | 模板四段都有 | 消息开头 |
| A2 | 这算不算"同一件事的第二个表示" | 不是，或旧表示在同一次改动里退场（`retirements.json` 登记） | 退场检查输出 |
| A3 | 新加的名词/常量/格式，声明在哪 | 只在 `packages/core/src/config/` 一处 | `health-check` 第 8、9 节 |
| A4 | 测试是先在红、后变绿的吗 | 修 bug 时：先把修复去掉确认它红 | 变异检查命令 + 两条结果 |
| A5 | 失败路径会怎样 | 失败能区分于"没有"；不吞异常；有上限 | 代码 + 测试名 |
| A6 | 文档同步了吗 | `state.md` 时间戳晚于代码；受影响文档已改 | `health-check` 4.7 |
| A7 | 我有没有用字符串替换改代码 | **没有**。改代码只用 `edit`/`write`；PowerShell 只做只读、git、构建、测试 | `health-check` 第 11 节：`✓ [体检]` |
| A8 | 这次改动动到语义字段了吗（实体类型、holder、来源、精度、状态、槽位） | 动到了 → 值域在 `config/` 一处声明；没有默认值；没有用"值的形态"推语义 | `health-check` 第 9.5 节 + `test/boundary.test.ts` |


## B. 功能或结构改动（A 之外再加）

| # | 问自己 | 算过 | 证据 |
|---|---|---|---|
| B1 | 需求/边界写下来了吗 | brief 里有"需求/文献/边界/验收"四段 | 文件链接 |
| B2 | 这个改法破坏了哪个旧假设 | 列出并检查（单写者？输入只含某类？失败会抛错？） | 说明里一段 |
| B3 | 多语句写入是否需要事务 | 需要就是一个事务；不需要写清为什么安全 | 代码或注释 |
| B4 | 是否新增了"判断出口" | 能并进已有调用（抽取/归纳）就并；不能才新开 | 说明里一段 |
| B5 | 旧的东西怎么办 | 删掉，或登记 `pending` | `health-check` 第 7 节 |
| B6 | 指标会变吗 | 说明哪个数会变、为什么；不会变的也说一句 | 说明里一段 |

## D. 大改动额外（代码审查，process 第 9 步）

| # | 要求 |
|---|---|
| D1 | 分区域并行审（不按文件大小切，按"区域 + 危险路径"切） |
| D2 | 每条发现带 `file:line` + 后果 + **验证方式**；给不出验证方式的不算发现 |
| D3 | 置信度 ≥80 才报（0=误报/旧问题，25=风格，50=轻微，75=确实，100=能复现） |
| D4 | "已复核"必须是跑出来的，不是读出来的——标签是承诺 |
| D5 | 只修有复现的；其余进 backlog，不混进这次改动 |

## 清单本身的账

- 机器能查的：A3、A6、B5、C1（`health-check` / `verify-installed`），**不用人记**。
- 机器查不了的：A1、A2、A4、A5、B1–B4、B6、C2–C4、D1–D5，**靠这份清单**。
- 每次改动贴的证据，就是下面这条判据：**没有一行机器输出的改动，等于没做完。**

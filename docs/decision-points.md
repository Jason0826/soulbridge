# 决策点与本地判定模型：参考笔记

> 状态：参考（2026-11-04）——**不是决定，不改现有实现，当前不做**。
> 读者：以后要评估「某个决策该不该上本地小模型」的人。
> 何时读：某个决策点的调用量 / 成本 / 错误数据开始出现时；或要设计一个新的判定环节时。
> 来源：[dsh-router-laya](https://github.com/HapyRain/dsh-router-laya)（Apache-2.0），读其 npm 包源码与 README 整理。

## 1. 一句话

它值得抄的是**骨架**——冻结标签、独立策略表、失败降级、评测闭环；不是那个 846MB 的模型，也不是它的七个标签。

## 2. 参考对象：它怎么做的

| 层 | 做法 |
|---|---|
| 模型 | `convaiinnovations/laya` 基座（ModernBERT-large 编码器 + 决策头）。**非自回归**：一次前向把「问题 + 选项 + 状态」拼成一个序列，选项前放 `[MASK]`，打分头给每个选项一个 logit。`noul` 题只有 false/true 两个选项，输出 `P(是)`。7 道题 = 7 次前向。 |
| 微调 | 383 条语料，在基座上微调 7 个冻结的布尔题（是否改文件、跨模块、步骤依赖、深推理、改代码、生成内容、多子结果全对）。第 7 题用三模型多数投票标注，本地 4070 SUPER 训练。自报准确率 99%、kappa 0.956——**自家金标，不可外推到我们的数据**。 |
| 策略 | 7 个布尔 → 6 条有序规则 → `low/high/max`；另有意图词典（"用最高档"/"继续"/"别用 max"）、重试升档、约束过滤。**模型只出标签，规则决定动作。** |
| 部署 | Python venv（`torch==2.14.0+cpu`、`transformers==5.17`、vendored `laya 0.3.7`）；`127.0.0.1:8765`，只有 `/judge` `/health` `/state`；单实例靠独占端口；加载约 70 秒、常驻约 2.9GB；权重 846MB，逐文件 sha256 校验；全程离线，任务文本不出本机。 |
| 代价 | 每轮判定 1–3 秒计入首字延迟；846MB 磁盘 + 2.9GB 内存 + 常驻 Python 进程。 |

**可抄的四点**：

1. **判定只回答一个标签，策略表单独放**——改策略不用重训模型。
2. **失败降级有明确落点**：服务不可达 → 落 `low`，会话不中断；判定超时也有 fallback 列。
3. **标签 id 是冻结契约**：只追加，不插入、不改名；规则引擎按 id 取值。
4. **评测闭环**：金标、一致率、失败率曲线；图表由实测数据生成，CI 检查图表过期。

**不能抄的两点**：

- **模型规模与运行时**：Python + torch 违反 core 零依赖（[ADR 0030](adr/0030-core-adapter-boundary.md)）。
- **它的七个标签**：那是在判「宿主任务难度」，不是记忆判断；换到我们的场景必须重新定义标签。

> 若以后复用其权重：Laya 基座与 ModernBERT 均为 Apache-2.0，再分发时保留上游 `NOTICE`。

## 3. 我们的决策点

| 决策 | 权威 | 频率 | 标签形态 | 错了的代价 | 现在的判断 |
|---|---|---|---|---|---|
| 值不值得记（抽取取舍） | [briefs/0025](briefs/0025-thread-extraction.md) · [ADR 0029](adr/0029-extraction-is-the-models-job.md) | 每条线索一次 | 有/无 + 类型 | 漏记不可见；脏记污染 | LLM 已在做。前置门能省调用，但要先有标注；**暂缓** |
| 新事实与旧事实的关系 | [RFC 0004](rfcs/0004-validity-supersession.md) · [briefs/0001](briefs/0001-validity-conflict.md) | 每条新事实 × 候选旧事实 | 矛盾 / 细化 / 重复 / 无关（有界 4 类） | 中；可降级为"保留旧的 + 标记" | **最像 Laya 的形状，优先候选** |
| 新消息接到旧线索还是新开 | [ADR 0034](adr/0034-attribution-defaults-to-continue.md) · [briefs/0017](briefs/0017-topic-threads.md) | 每轮 | 二选一 + 候选 | 中 | 规则 / 相似度够用 |
| "她"指谁 | [ADR 0032](adr/0032-two-layers-of-memory.md)（人物层，尚未实现） | 每次提及 | 候选排序（**开放集**） | 高 | **不做分类器**；候选生成 + LLM 消歧 + 低置信不注入 |
| 缺口是否成立 / 张力多少 | [briefs/0016](briefs/0016-extraction-consolidation.md) · [ADR 0032](adr/0032-two-layers-of-memory.md) | 每次抽取 | 数值 | 低 | 规则 |
| 注入哪些 | [briefs/0020](briefs/0020-retrieval-funnel.md) | 每轮 | 排序 | 中 | 评分，不是分类 |

一句话排序：**pair 分类（冲突判断）最适合小模型；开放集（指代）最不适合；其余用规则 / LLM 更划算。**

## 4. 引入判据（五条，缺一不做）

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | 高频 | 先量出调用次数；低频决策上模型，运维成本摊不平 |
| 2 | 标签有界且可标注 | 标签能枚举、能写金标、能算 precision / recall / kappa |
| 3 | 错误可降级 | 模型不可用或低置信 → 规则 / LLM 兜底，不阻断主链 |
| 4 | 经济性 | 省下的 LLM 调用 × 单价 > 运维成本（内存 / 磁盘 / 延迟 / 维护） |
| 5 | 过四关 | 输入有闸门、最差有地板、效果有指标、出错可回退（[ADR 0031](adr/0031-model-dependency-acceptance.md)） |

## 5. 如果启动，按这个顺序

1. **先做端口，不做模型**：`decide(input) -> { label, confidence, source: 'rule' | 'llm' | 'model' }`，业务只认 label（同 `LlmFn` 的思路）。
2. **冻结标签协议**：id 只加不改，规则引擎单独放；每个标签写清"什么算、什么不算"。
3. **先有标注**：从书测（[briefs/0015](briefs/0015-book-recall.md)）产出指代对、矛盾对、"值得记 / 不值得记"三类金标。
4. **先用规则 / LLM 实现**：模型只是第三个实现，不是起点。
5. **模型形态**：优先蒸馏 + ONNX（Node 内可跑），或独立 sidecar（像 Laya 那样）；**不进 core**。
6. **验收**：每个标签单独算准确率 / 召回 + 失败率曲线；低置信不注入。

## 6. 非目标

- 不做生成式小模型（判定是分类，不是写作）。
- 不把判定模型放进 `packages/core`。
- 不用它替代 [ADR 0029](adr/0029-extraction-is-the-models-job.md) 的"抽取是模型的活"。
- 不做用户自定义标签——等真的出现第二个消费者。

## 7. 启动条件

现在**没有基线数字**，所以不设拍脑袋的阈值。启动前先补三组数：

```
1. 抽取调用量：每天 / 每条线索几次、平均 token、单价
2. 被判定为"不值得记"的比例（现在没有，因为 LLM 一次完成）
3. 冲突 / 指代的真实错误条数（来自注入后的错误，不是猜测）
```

三组数出来后再定阈值；阈值必须是能从基线算出来的数（[rules.md](rules.md) 第 37 条）。

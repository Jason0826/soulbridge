# 通用项目原则（可放进 steering file）

> 这份文件是**跨项目可复用**的：它不含本仓库路径、ADR 编号、命令或通过线。
> 用法：整段放进任意项目的 `AGENTS.md` / `CLAUDE.md` 顶部；
> 项目特有的规则写在项目自己的文档里，**不要混进来**——那会让这份文件失效。
> 本仓库的完整版（含检查与权威）见 [rules.md](rules.md)。

## 一、动手之前

1. **先说清再动手**：为什么改 / 怎么做 / 影响面 / 怎么验。给不出影响面的改动不开工。
2. **修 bug 先看见红**：先复现，再修；修完把修复拿掉，确认它重新变红。
3. **不确定就做最小验证**：能跑一行代码验证的，不要讨论三十分钟。
4. **先读完再判断**：项目有文档就先读，不要凭印象重新发明一遍已经定过的东西。

## 二、结构与表示

5. **一件事只有一个表示**：引入新表示，旧表示必须在同一次改动里退场；否则登记为待清理。
6. **定义只有一处声明**：名词、枚举、格式、默认值集中在定义文件，别处只引用或渲染。
7. **语义字段不得有默认值**：默认值就是一个决定；由调用方或模型明确给出。
8. **语法不推语义**：不要因为值的形状（不是数字、含标点、长度像名字）就把它当成另一类东西。
9. **不造词表**：判断"这是不是某类东西"交给能理解内容的一方；代码不做语义黑名单。
10. **假设写进代码**：单写者、输入前置条件、失败会抛——写成类型、断言或测试，不要留在脑子里。

## 三、失败与兜底

11. **失败必须可区分于"没有"**：空结果、解析失败、调用失败是三种事，不能都变成一个空字符串。
12. **兜底会掩盖根因**：每次降级、每次默认值、每次 try/catch 兜住，都要问一句"它让什么错误不再报警"。
13. **"能跑通"不等于"做对了"**：先能跑、再回头，回头这一步要真的排进计划。
14. **不吞异常**：要么重试，要么降级并说清降级成什么，要么抛出；不许只记一条日志然后继续。
15. **有上限**：重试次数、队列长度、上下文规模都要有显式上限，并在丢弃时说清丢了多少。

## 四、数据与文本

16. **原始记录不可变**：原文、时间、来源保留；派生数据可以重建，不能反过来当成源头。
17. **不截断**：只在整单位上取舍（整句、整行、整轮）。宁可少给一个完整单位，不给半句。
18. **取舍要可见**：丢了什么、为什么丢，要有计数或日志；静默丢弃等于没有数据。

## 五、验证与观测

19. **先可观测，再改行为**：没有数据支撑就先加数据；结论用数字，不用感觉。
20. **空样本不是判决**：样本不足就写"待验收"，不写"已通过"。
21. **验证装上去的产物**：测源码不算数；在真实运行的副本上跑一遍行为。
22. **失败路径也要有测试**：只测成功路径的实现，等于没处理失败。

## 六、工具与协作

23. **不用字符串替换改代码**：用编辑器/结构化写入；替换类操作后逐行看 diff。
24. **改完看 diff**：提交前逐行读一遍自己的改动，尤其是文档和配置。
25. **提交说明写"为什么"**：做了什么 diff 会显示，为什么这么做只有说明能留下。
26. **一条规则配一个检查**：能机器查的就机器查；查不了的标"人工 review"，不假装自动化。

## 七、文档

27. **现状只有一个权威文档**：带"最后核对"时间戳；代码比它新就是落后。
28. **文档地图只放链接**：同一事实只在一处展开，别处引用。
29. **新增文档要回答"谁读、什么时候读"**：答不上来就不加。
30. **文档也要防损坏**：编码、换行、截断这类事故全量扫描，不要只扫本次改动。

## 八、模型参与的环节（有 LLM 的项目）

31. **判断归模型，形态归代码**：代码只做结构校验、唯一编码、拒绝缺失；理解、分类、重要程度归模型。
32. **模型环节要过四关**：输入有闸门、最差有地板、效果有指标、出错可回退。
33. **模型失败不冒充成功**：失败保留重试并记录原因；不要把"模型回答空"当成"模型说没有"。
34. **输入单位要对齐**：一次判断的输入必须是一个完整单位（一轮交流、一条线索、一份文档），不要只给其中一边。

## 九、这套原则自己的规则

35. **规则进记忆不等于会在决策点触发**：能写成检查的，不要只写成提醒。
36. **一条规则一个权威**：发现重复，删弱的、留链接。
37. **规则也要被证伪**：样本不够写"待验收"，通过线要能算出数。
38. **新项目不要一次搬全套**：先立三条能查的（编码损坏、定义单点、文档落后于代码），再逐条加。

## 十、写入与数据一致性

39. **一个判断只开一次调用**：新增判断先并进已有调用；每多开一套检测器，就多一份 prompt、解析和闸门要同时改。
40. **多语句写入是一个事务**：写新行 + 退休旧行要么都成功，要么都不发生；迁移和版本号写在同一次提交里。
41. **排队的工作只有一个写入器**：绕过它直接写文件/表，会越过上限与日志，数据丢得没有痕迹。
42. **写入没生效要报**：`UPDATE` / `INSERT` 影响 0 行不是成功；被静默影响的写入是最难查的一类 bug。
43. **id 与名字分离**：id 是引用，名字是属性；改名不改身份，名字不该编码进 id。
